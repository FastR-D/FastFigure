# 用户提供的可编辑绘图素材

两套参考用于扩充计算机科研组件、容器和布局表达。当前已增加神经元、圆形融合算子、三维特征体和梯形投影层四类图元，共五个新组件种子；它们是从参考中提炼的参数化实现，尚未将两份素材整体导入产品。

## 本地 PPTX

[模板合集](/home/gugumur/下载/模板合集20260627.pptx) 包含 29 页。按 presentation relationships 解析实际页序后，XML 清单记录 2,007 个 shape、1,454 个 connector、132 个 group 和 26 个 picture。shape 计数包括 AlternateContent 的备选表示，不能直接当成同时可见对象或独立组件数。

常见预设几何包括矩形、圆角矩形、椭圆、cube、梯形和平行四边形。原生对象和分组为提炼特征体、重复模块、算子、分支和子图边界提供了来源。第 15 页已渲染查看，包含完整科研架构与简化图元版本，可对照其中的不同颜色分区、虚线阶段、特征体、C/+ 等算子与跨组连接。

连接线需要特别区分：303 条具有两端引用且引用 ID 可在对应页解析，304 条仅有一端引用，847 条没有端点引用。这里验证的是 XML 引用，不是 PowerPoint 中移动对象的实测效果。不能从原生连接器类型推断每条线都绑定完整。

建议采集时保留 slide、shape ID、原始分组、xfrm、几何与文字；对未绑定的端点单独恢复和验证。分组粒度需要检查，不能把每个 Office group 自动升级为科研组件。旋转、翻转和组坐标变换应在后续导入器中明确处理。

可重复的只读清单工具：

```bash
python scripts/inspect-pptx.py /absolute/path/to/reference.pptx --out /tmp/reference-objects.json
```

该工具保留原始 DrawingML 变换与父子关系，不执行宏、嵌入内容或外部关系，也不把局部坐标冒充绝对坐标。完整对象清单留在本地检查目录；仓库保存 [来源摘要与指纹](editable-material-sources.json)。

## 对当前实现的影响

- 图元增加 neuron、operator、volume 和 projection；神经元与算子默认使用圆形尺寸，投影层按其可见边界计算侧面端口。
- 组件种子移到 `src/data/components.ts`，记录来源描述与参考页；预览、画布渲染、类型选择和 draw.io 编译同时扩展。
- 容器使用统一父子模型，支持组合、嵌套、解组和子树移动；内部与跨组连接使用稳定节点 ID。
- 子容器可以覆盖皮肤与色系，并继承未覆盖的父级样式。加入浅砂黄和浅玫红作为图件色系，界面品牌保持蓝色。
- draw.io 导出采用父级相对坐标，连接放在两端的最近共同容器下；视觉皮肤仍需在目标编辑器中验收。
- 参数化组合已提供全连接网络、多分支融合与处理流水线；前两类分别参考公开 ML 素材和本地模板的结构表达，第三类为程序化布局。它们由原生图元生成，包含创建参数及来源，未直接复制源文件对象。
- 可以将修改后的容器存入本地组件库，再导出、导入和复用。派生记录保留上游配方参数和来源，也允许补充人工引用；当前不提供整库自动采集或服务端同步。

后续继续提炼可变深度的特征堆叠、残差分支和多尺度融合，并补充对外暴露的语义端口、参数更新及布局约束。这些复合组件应复用统一容器与节点模型；仅保存一张参考截图不足以支撑它们的局部编辑与组合。
