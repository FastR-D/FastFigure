# 计算机科研绘图素材库与生成闭环调研

研究日期为 2026 年 10 月 28 日。目标用户是计算机类期刊和会议作者，核心设想是：收集多样论文图，通过程序和大模型重绘，积累可复用素材；新图可以检索参考后直接绘制，也可以由 GPT Image 生成视觉草稿后重建，再将校正成果回收入库。

**这个方向已有相近研究支持，建议将 FastFigure 建成带可执行组件库的科研绘图系统。** 参考图负责展示设计经验，重绘后的图与子图保存编辑结构，参数化组件负责稳定复用，质量验证决定哪些成果进入正式库。RSI 同时改进重绘器、组件程序和生成策略，具体方案见 [矢量化与 RSI](2026-10-28-vectorization-rsi.md)。

产品范围限定为计算机科研绘图。PDF、扫描件格式化和全文重排相关工具仅用于研究可迁移的解析、重建和迭代方法，不建设 PDF 产品或扫描件辅助管线。容器与手绘等可定制样式纳入核心研究，见 [容器与样式方案](2026-10-28-container-styles.md)。下文的规模、流程和实验指标属于研发建议；项目能力按一手资料记录，未运行其模型训练或付费生成服务。出处与静态检查记录见 [本轮来源索引](cs-research-sources.json)。

| [DiagramBank](https://github.com/csml-rpi/DiagramBank) | 带标题、摘要、caption、图内引用上下文、来源与过滤标记的示意图库 | 参考图检索与采集元数据的重要起点 | 以图像与文档上下文为主，不能直接当成可编辑组件库 |
| [PaperVizAgent](https://github.com/google-research/papervizagent) | 检索参考，规划内容和风格，再生成与修改；原名 PaperBanana | 借鉴参考图如何进入规划过程 | 实现中的候选池排序是研究基线，不是面向海量图库的完整检索服务 |

| [FigTree](https://github.com/yepengliu/FigTree) | 按层级分解画布，生成局部 SVG，渲染检查后组合；跨子图连接由共同父层处理 | 适合复杂方法图的分块生成与修正 | 可参考模块边界与局部修复，不应把长 SVG 程序当成最终唯一数据库 |
| [SciFig 研究系统](https://arxiv.org/abs/2601.04390) | 内容规划、层级布局、组件渲染和迭代反馈，输出可编辑 XML；有专门评测集 | 图结构规划与科学内容评价的补充 | 与同名商业网站分别记录；作者成绩没有在本地复现 |
| [Edit Banana](https://github.com/BIT-DataLab/Edit-Banana) | 分割、OCR、公式识别和 DrawIO XML 生成；文档说明线上服务与仓库版本不同 | 图像重建与混合素材恢复基线 | 必须按所测代码版本记录对象表示和效果 |
| [OXR](https://github.com/SoMarkAI/OXR) | 文档解析与后训练 RSI 思路：找错、归因、生成针对性数据、训练 | 借鉴错误驱动的数据与模型改进闭环 | 文档解析与图内矢量对象恢复是不同任务；RSI 迁移设计见专文 |

FigAgent 的关键启发是把常见图件片段抽象为有参数的绘图程序；位置、尺寸和样式可以调整。FastFigure 可据此进一步建立端口契约、跨格式编译和参数变化验证。后面三项是产品设计建议，不是对 FigAgent 已实现能力的转述。[FigAgent 方法](https://arxiv.org/html/2603.29590v2)。

## 3 计算机图件的采样范围

下面列的是采样入口示例，不是对会议、期刊排名或统一投稿规范的判断。第一批可以兼顾近年图件与少量经典结构，并对同一论文的预印本、会议版和期刊版做归并。

| 领域 | 会议和期刊入口示例 | 优先积累的视觉结构 |
| --- | --- | --- |
| AI 与机器学习 | NeurIPS、ICML、ICLR、AAAI、TMLR、TNNLS | 训练与推理分流、优化回路、模型模块 |
| 视觉与多媒体 | CVPR、ICCV、ECCV、ACM MM、TPAMI | 特征金字塔、多尺度、跨模态、空间与时间结构 |
| NLP 与信息检索 | ACL、EMNLP、SIGIR、KDD、TKDE | token 序列、检索与生成、索引、知识图、排序流程 |
| 系统与网络 | SOSP、OSDI、NSDI、SIGCOMM、TOCS | 服务部署、数据与控制通路、协议时序、队列、缓存 |
| 数据库与数据管理 | SIGMOD、VLDB、ICDE、TODS | 查询计划、算子树、索引、事务、存储层次 |
| 安全与隐私 | S&P、CCS、USENIX Security、NDSS、TDSC | 信任边界、攻击与防御路径、参与者与协议消息 |
| 软件与程序语言 | ICSE、FSE、ASE、PLDI、POPL、TSE | CFG/AST、状态机、程序变换、分析框架 |
| 硬件与体系结构 | ISCA、MICRO、ASPLOS、DAC、TC | 流水线、互连、存储层次、芯片与模块结构 |
| 图形学与交互 | SIGGRAPH、CHI、UIST、VIS、TOG、TVCG | 渲染管线、交互流程、空间示意、多面板结果 |

领域标签之外，再独立标注视觉类型：线性流程、双分支融合、循环反馈、分层框图、树、关系网络、协议时序、泳道、状态机、硬件结构、张量与矩阵、数据图、多面板，以及截图与结构混合图。同一张图可以有多个类型。

这能让“检索系统论文里的模块化框图”和“找一张横向双分支布局”成为不同查询。会议名与作者声誉只作为来源信息，不用作图件质量的直接分数。

## 4 素材库分为五层

| 层 | 保存什么 | 新图怎样使用 | 入库要求 |
| --- | --- | --- | --- |
| 参考整图 | 原图、caption、上下文、领域、版式、来源 | 检索构图与表达方式 | 可追溯、裁剪完整、类型可识别 |
| 可编辑整图与子图 | FigureIR、SVG、draw.io、源程序、对象对应 | 直接修改或抽取局部结构 | 文字、拓扑、几何与编辑行为有检查记录 |
| 参数化组件 | 渲染程序、参数、端口、约束、预览与变体 | 调用函数生成 encoder、缓存层、队列等 | 参数变化和组合后仍然有效 |
| 布局配方 | 组件槽位、关系模式、对齐、间距与边界端口 | 组合双分支、训练推理、协议交互等 | 组件数量和标签长度变化时可布局 |
| 样式规范 | 字体、线宽、色板、容器边框与标题、填充、手绘笔触、标号、目标物理尺寸 | 给同一结构切换论文风、手绘风等样式 | 拓扑不变；笔触可复现；最终尺寸清晰且可编辑 |

五层通过父子关系连接。一个组件可以追溯到哪些图与哪些区域，使用过哪些重建或人工修正；一张新图则记录用了哪个布局、哪些组件版本和哪些参考。参考整图进入库，不必立即承担重绘成本。

组件粒度应能承载一个可复用的视觉概念。矩形和箭头属于基础图元；attention block、双队列、存储层次、查询算子树片段更适合成为科研组件；完整模型架构通常保留为整图示例或布局配方。这个粒度划分需要用实际复用和修改时间验证。

## 5 收集与重绘管线

### 5.1 先建立图与论文的对应关系

用 [DBLP](https://dblp.org/) 的计算机文献元数据建立 venue、年份、DOI 和论文记录；实验使用可复现的快照，而不是每次重新获取变化的日常数据。[DBLP 快照建议](https://dblp.org/faq/4621382.html)。

再按来源接 OpenReview、arXiv、作者仓库和可访问的会议论文入口。OpenReview 提供按 venue 查询 notes 和取 PDF 附件的方法；arXiv 为元数据和 PDF/source 提供不同的批量入口。[OpenReview 获取资料](https://docs.openreview.net/how-to-guides/data-retrieval-and-modification/how-to-get-all-notes-for-submissions-reviews-rebuttals-etc)、[arXiv 批量入口](https://info.arxiv.org/help/bulk_data.html)。

每条图件保存论文版本、页码、图号、bbox、caption、正文引用段落与原文件指纹。仅有图像 embedding 不足以表达论文中的模块含义和图件用途；caption 与引用段落应进入检索文本。

### 5.2 优先利用已有源结构

PDF 提取属于离线素材准备或外部工具参考，FastFigure 接收其中与图件相关的证据；不建设页面管理、PDF 编辑或全文重排功能。

按下面的顺序选择处理路径：

1. 有原作者程序、TikZ、SVG、draw.io、PPTX 等源文件时，先解析与渲染它们，并保留来源。
2. 只有 PDF 时，提取可用文字、路径和图像，再恢复对象层级。PDF 不保证保留作者的分组和连接关系。
3. 只有栅格图时，使用 OCR、几何分析、分割与视觉模型恢复结构描述，再生成 FigureIR 或图形程序。
4. 渲染后对照原图，分开检查文字、关系、几何、视觉与导出结果。
5. 审核通过的图才进入可编辑库；只需构图参考的图可以停留在参考层。

[PDFFigures 2](https://github.com/allenai/pdffigures2) 是计算机论文图号、caption 和区域提取的经典基线，其输出不负责图内语义对象恢复。可与现有文档解析器对照，尤其检查多面板裁剪和 caption 对齐。

### 5.3 两种重绘器并行比较

| 重绘器 | 建议流程 | 优先测的图 |
| --- | --- | --- |
| 通用视觉大模型 | 先恢复标签、模块和关系，再生成受约束 IR 或程序；渲染后局部修正 | 复杂整图、罕见结构与长标签 |
| 专用图像到 SVG 模型 | 用 VFIG 等作基线，解析输出并补分组、端口和显式边 | 常见框图与批量组件候选 |

不要只比较生成的 SVG 是否能打开。对组件库来说，修改标签、改变数量、横竖布局切换后是否仍然可用，更能决定是否值得保留。

### 5.4 把重绘图提炼为组件程序

对重复出现的视觉片段，先由大模型提出组件边界、参数和端口，再转成可调用程序。将特定论文的标签、坐标和颜色替换为参数，把连接与包含关系保留为约束。

组件程序建议输出 FigureIR，由编译器负责 SVG、PPTX、draw.io。已有 TikZ 或 XML 片段可先作为适配器封装；逐步把高频组件转换为统一表示。这样可以在保留现有资产的同时，逐步获得跨格式编辑能力。

## 7 检索时给参考图分配职责

### 7.1 查询先变成绘图需求

新任务先整理为内容规格：必须出现的模块、关系与方向、可用数据、标签与公式、分组层级、图的用途、目标尺寸和已有素材。当前论文内容是科学事实来源，参考图提供表达方式。

对“用几张素材库图片作为基础”，建议显式指定每张的职责：一张参考全局布局，一张参考局部组件的表达，一张参考样式。若几张参考在流程方向或模块含义上冲突，规划器应先根据当前内容规格解决，再绘图。

### 7.2 分开召回再重排

| 检索轴 | 主要特征 | 解决的问题 |
| --- | --- | --- |
| 内容 | 方法段落、caption、领域概念、组件类型 | 模块含义是否匹配 |
| 结构 | 节点与分组数量、分支、环、层级、端口、重复模式 | 能否借用关系结构 |
| 版式 | 宽高比、阅读方向、面板、留白与密度 | 能否适应目标画布 |
| 样式 | 字体层级、色板、线型、图标与几何风格 | 能否统一视觉 |
| 可用性 | 审核状态、格式、来源、参数验证与复用记录 | 资产能否直接调用 |

第一阶段可使用文本与多模态 embedding、结构标签和元数据过滤，召回几十个候选后，用小规模重排选出少量互补参考。组件检索返回函数签名、参数、端口与预览，整图检索返回图像和结构摘要；不必把所有 SVG 源码塞入同一个提示词。

静态检查 PaperVizAgent 的 [retriever](https://github.com/google-research/papervizagent/blob/main/agents/retriever_agent.py) 发现，所查版本的 diagram 自动模式把有限候选的 caption 与方法内容交给模型排序；[planner](https://github.com/google-research/papervizagent/blob/main/agents/planner_agent.py) 再读取选中示例的文字与图片。这可以作为可复现基线；大图库需要另外建立索引、过滤和候选预算。

## 8 两条新图生成路线

### 8.1 直接组合与绘制

```mermaid
flowchart LR
    A[论文内容与绘图意图] --> B[内容规格与关系图]
    B --> C[检索布局 组件 样式]
    C --> D[选择并参数化组件]
    D --> E[FigureIR 与确定性编译]
    E --> F[渲染 检查 局部修改]
    F --> G[可编辑新图]
```

适合方法框图、协议、系统结构、训练与推理流程。图结构较明确时，优先调用已验证组件，在必要位置生成新组件。首次生成后，图内标签、节点和连接关系可以继续修改。

### 8.2 GPT Image 生成视觉草稿再重绘

```mermaid
flowchart LR
    A[内容规格与参考职责] --> B[GPT Image 视觉候选]
    B --> C[核对内容与关系]
    C --> D[分块解析并检索组件]
    D --> E[程序与 LLM 重建]
    E --> F[与内容规格及草稿分别对照]
    F --> G[可编辑新图与候选素材]
```

适合需要新构图、复杂空间表达或更丰富视觉语言的图。草稿提供设计探索；重建时以内容规格核对模块、文字、公式和关系，并用组件库恢复重复结构。

OpenAI 文档支持参考图编辑等图像工作流，输出为 PNG、JPEG、WebP 等图像；文档同时列出精确文字布局和结构敏感构图的局限。因此，图像生成与对象重建需要分别验证。[GPT Image 文档](https://developers.openai.com/api/docs/guides/image-generation)。模型标识、参考图处理选项和调用预算应配置化，避免固定在某一代模型。

还有一种可以单独试验的折中：整体采用结构化组件与文字，只让图像模型生成少数需要视觉创作的局部素材。它是否比整图生成更节省修正时间，要在同一批任务上对照。

## 9 回收入库与来源谱系

每次生成保存所用内容规格、参考 ID、组件版本、模型与提示配置、程序、渲染、评价和修改记录。通过验证的结果可以升级资产；仅仅生成成功或看起来漂亮，不直接升级为正式可复用组件。

建议采用以下状态流：原始参考 → 重建候选 → 校验过的可编辑图 → 组件候选 → 通过参数验证的组件。失败结果进入错误库，供 RSI 使用；重复结果合并为已有资产的变体。

| 回收结果 | 建议去向 |
| --- | --- |
| 新构图但结构尚未校对 | 生成候选区 |
| 图准确、仍带论文特定语义 | 可编辑整图或子图 |
| 可改参数且端口稳定的局部结构 | 正式组件库 |
| 新配色、字号和线型组合 | 样式候选 |
| 错字、漏边、绑定丢失或参数变化失败 | 错误库与修复任务 |
| 用户修改过局部 | 记录该局部的前后差异与修改意图，不自动把全图视为已校对 |

来源管理是共享库的数据字段。arXiv 说明不同论文乃至版本可能采用不同许可；CVF 开放阅读页面也保留对原权利人的说明。应保存素材来源和适用范围，分别处理原图参考、衍生图、公开共享和训练数据，而不能从可下载推导所有用途。[arXiv 许可说明](https://info.arxiv.org/help/license/index.html)、[CVF 开放页面说明](https://openaccess.thecvf.com/menu/CVPR_2023)。

## 10 首轮数据与路线实验

建议先做 50 张代表图的流程验证，再建设 300 张真实图的研发集。下表是采样计划，不是已经收集的数量。

| 领域组 | 建议图数 |
| --- | --- |
| AI 与机器学习 | 50 |
| 视觉与多媒体 | 40 |
| NLP 与信息检索 | 40 |
| 系统与网络 | 45 |
| 数据库与数据管理 | 35 |
| 安全与隐私 | 30 |
| 软件与程序语言 | 30 |
| 硬件、图形学与交互 | 30 |
| 合计 | 300 |

这 300 张按论文及其派生谱系划分开发、验证和最终验收，建议为 180、60、60。另建程序生成集，提供已知结构的训练样本和测试题，按组件家族与生成器模板分组，避免只是更换配色就跨集合。

初期目标可以是 60 个通过参数变化验证的组件、20 个布局配方和一小组样式。它们是预计建设目标，需要根据首轮覆盖率与实际复用率调整。

### 10.1 同一任务做六组对照

| 组别 | 路线 | 用来回答什么 |
| --- | --- | --- |
| A | 无图库，直接 LLM 绘图 | 没有积累的基础水平 |
| B | 检索整图后直接绘图 | 参考图库是否有增益 |
| C | 检索整图、子图和参数化组件后绘图 | 组件程序是否减少错误与修正时间 |
| D | GPT Image 出图后通用重建 | 视觉创作与重建的基础成本 |
| E | GPT Image 出图后结合组件库重建 | 素材库是否改善混合路线 |
| F | 固定路线叠加 RSI 版本迭代 | 系统是否在独立样本上持续改善 |

固定内容规格、尺寸、调用预算与停止规则。除视觉评价外，记录关键文字与关系、原生编辑能力、参数变化、总调用成本，以及研究者修改到可用状态的时间。

## 11 对当前研发顺序的调整

第一步先定义素材契约与错误分类，并用少量手工确认的组件生成已知答案样本。第二步接入真实图解析与重建，建立整图和组件的对应。第三步比较直接组件生成和 GPT Image 草稿重建两条路线，再加入基于错误归因的 RSI。

首版可以先让检索与组件程序迭代，不必等待模型权重训练完成。待错误分布、可靠标签和评测稳定后，再评估针对重绘模型的 SFT 或其他后训练。这个分阶段安排与用户提出的 RSI 方向兼容，且每个阶段都能独立验证是否值得扩大投入。
