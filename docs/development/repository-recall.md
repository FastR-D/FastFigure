# 助手自动召回本机素材

第四十四批将本机持久库接入普通绘图与方案规划，第四十五批改进整段取词与常用双语名称。浏览器中没有工作组件，也可在发送时直接读取合适的本机快照，随后由模型判断是否复用；不需要先取回到浏览器 50 项工作缓存。

## 使用与范围

左侧助手的“参考组件 → 按要求自动检索”中，默认勾选“发送时自动检索本机素材库”，偏好随模型设置保存。发送前显示工作组件和内置素材候选；发送后，本轮“本机素材召回”展示实际附带清单、命中词和快照指纹。点击素材名可核对原生结构及来源。

第五十批起，本机库的归档项在排序与候选截断前排除，普通召回与助手筛选一致。运行或方案已冻结的清单、现有工作副本和图件继续保留；按 SHA 查看来源仍可打开归档快照。详见[归档范围](component-archive.md)。

“已附带”表示已进入模型上下文，不代表模型实际使用；真正插入的对象仍在“复用组件”中报告。模型可不使用召回结果，候选仍需人工应用。

仅普通直接绘图和首次规划可检索。手动选择、不使用组件、数据选图、带实际图谱的重建和分区修复保持各自素材边界。采用方案后沿用规划时完整冻结的参考，不因当前文字或库变化重新召回；详情标明来源方案。关闭勾选后，自动模式只使用工作组件与内置素材。

第四十六批增加可选的“先由助手筛选素材”：在至多 24 项冻结文字候选中按完整要求、原生目录与配方声明逐项取舍，再把至多六项交给绘图 / 规划。默认关闭，增加一次模型调用；失败不自动回退，方案采用不重筛。操作、证据和边界见[助手逐项筛选](repository-selection.md)。未开启时继续使用以下纯文字路径。

## 检索与冻结

当前引擎为 `metadata-keywords-v2`，记录版本为 2，仅做文字匹配：

1. 扫描整段要求，优先保留已有种子 / 配方名称的常用中英文别名，如编码器 / encoder、张量 / tensor、流水线 / pipeline、图像分块 / patchify、分块嵌入 / patch embedding。只翻译明确名称，不把 Encoder 等同于 Transformer，不把张量等同于特征图或将 Attention 等同于 Softmax；Patch Embedding 不等于完整 ViT 编码器。
2. 名称覆盖的片段不再生成碎双字；其余文字仍提取拉丁字母 / 数字词及中文相邻双字，去重、过滤部分常见词。在剩余预算中按全段位置等距取样，包含首尾；至多 32 组，每组至多六个名称变体。记录原词、展开词和未参与的候选词数，不再只截取开头。
3. 在库的检索文本中按命中的词组数粗排；同组翻译只计一次，最多取 24 个候选，超过时报告截断。细排按标识 / 名称 / 标签 / 说明 / 来源分别赋予 12 / 8 / 5 / 2 / 1 权重，同字段同组只计一次，英语需匹配词边界，取至多六份快照；每类显示至多八个实际命中词。权重不是视觉或科学质量分数。SQL 粗排仍为文字子串，可能有假阳性占位，尤其在候选池截断时。
4. 读取完整快照并重验 SHA，追加便携派生记录，与发送前参考共同排序，最终合并为至多六项。精确相同的工作快照去重；原组件 ID 相同的不同版本保留独立身份。新标识若与手工工作副本冲突，分配确定的后缀，保留双方。
5. 在模型执行前冻结实际结构。模型收到匹配边界、素材描述、节点别名、接口、配方及来源；服务使用冻结结构编译候选。不会把库内全部图件放入请求或改写浏览器工作库。

单项损坏或来源链已满时标为不可用，其余参考继续；整个库不可用则在模型调用前报错，可关闭库检索再用工作组件。不自动修复或覆盖原证据。界面和历史保存轻量召回记录，没有复制整套素材或缩略图到每条历史。

请求字段为可选 `librarySearch:boolean`，直接调用 API 时缺省不检索。客户端仅在相应自动模式发送 true；服务再次校验任务边界。程序产生只读的 `summary.repositoryRecall`，模型响应不能伪造。采用方案的报告含 `fromPlanRunId`。

纯文字名称命中不解析否定或保证具体结构 / 参数符合要求。“无掩码注意力”仍可能同时召回因果项，“不要解码器”也可能正向命中解码器；界面与模型提示均说明边界，实际结构须按完整要求核对，模型可不使用。可选模型筛选用于判断这些取舍，仍不证明科学正确性。检索词详情可查看本轮 32 组预算与实际别名。

## 缺省配色用途

本批真实调用给出完整、合法的源 / 目标色槽，却漏了五条 `colorMap.role`。角色说明不影响确定的换色关系，现允许缺省，并由程序明确标记“用途未注明”；不会据颜色补出科学语义。

未知配色、来源色槽不存在、索引越界、重复来源、错误字段类型及数据图表限制保持校验。明确提供的角色保留；已采用风格 / 方案规定的完整映射仍需保持。界面会显示未注明用途，原始响应可回看。

## 验证

现有文件新增召回场景和真实遗漏字段回归，覆盖双语命中词、候选池 / 词预算、同 ID 多版本、工作快照去重、命名冲突及坏项隔离。双 CLI 用例验证服务读取本机库、运行中新增版本不改变当前图、采用方案不重检索、历史保留清单。现有助手 UI 流程验证浏览器工作库为空时自动召回、查看源快照与保持待审；UI 仍为五个文件、四条 1920×1080 流程。

第四十四批的 Lint、类型、528 项核心 / 服务检查、构建及四流程通过，UI 用时 21.93 秒。既有 Vite 导入 / 包体积和 Node 22 SQLite 实验提示仍在。默认检查继续使用独立目录和 CLI 夹具。

第四十五批在现有服务文件中增加整段末尾覆盖、双语同组不重复计分、名称边界及相关结构不混同的场景；原双 CLI 冻结和方案复用检查继续运行。助手现有流程核对本轮别名及源快照，没有新增 UI 文件。离线对照与限制见[固定相关性样例](../../benchmarks/component-retrieval-v1/README.md)：开发十例首项 6→10，预留六例 2→6，但两例限制仍返回禁止项，预留清单同时满足首项与禁止项检查仅 4/6。这是同作者自制样例，不是独立质量结论，本轮没有实际模型调用。

本批 Lint、类型、529 项核心 / 服务检查、构建和四条 1920×1080 UI 流程通过；UI 22.514 秒，仍为五个文件。已查看实际助手截图中的词组、命中字段和待审状态。

## 一次实际调用与原响应离线编译

在独立目录准备因果注意力、无掩码注意力和张量栈三份自制素材；客户端请求没有任何 asset 快照。服务召回两份注意力，与内置候选合并为六项。一次 Codex CLI 0.165.0 调用，运行 `8d15920a-2d84-462b-aef2-918a71d96464`，96.322 秒，具体模型身份未报告。

模型明确选择已存因果注意力，解释无掩码和简化模块不适用，返回 `fit=948×494`、统一英文标题和无标题栏根组合，清空原生重复标题。原运行因五条色映射缺少 role 被拒绝，原始失败与响应保留。

允许用途说明缺省后，不改原响应、零追加模型调用离线编译：69 个原生图元、9 条内部语义边及四接口保持，另加两处文字，共 71 个图元；实际比例 `0.9673469387755103`，相对几何最大数值误差约 `1.71e-13`。源标签仅按模型声明覆写，拓扑 / 绑定 / 快照来源保持，全部连线 clear，21 个原生文字字段无截断报告。五条用途由程序记为“用途未注明”。已查看实际渲染，标题无重复；两处底部说明仍有语义重复，保留待审。

第四十四批当时的召回代码重算清单与原冻结记录完全相同，不能以这句话声称后续 v2 清单相同。证据在 `test-results/repository-recall-live-codex-v1/`，包含三份来源、数据库、输入、提示、原响应、失败运行和源码；`offline-compile-v1/` 保存当时新契约编译的图件 / SVG / PNG / 捕获组件及核对记录。原响应 SHA 为 `bdb511641250774cbf84fc7d93229db0db2efeae3ea3ff624edfb466a113b4f2`。

原运行仍是失败，离线编译不是修正后的真实重跑；结果未应用到用户工程或自动入库。这是纯文字、三份自制素材的能力样例，不是受控前后对照、真实论文检索质量、科学正确性或 RSI 结论。
