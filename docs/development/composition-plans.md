# 可审阅绘图方案与数据表达目标

第卅二批，2026-10-29。方法图可先规划再显式采用；数据图表继续使用独立的原始表选型通道，并补充导入时的研究目标。

## 方法图：先规划，再生成

左侧助手的“本轮任务”选择“先规划绘图方案”，附带至多三张参考图及原生组件。模型返回分区、阅读顺序、图示、简短注释、连接关系、容器样式、配色、字体建议、逐图观察和核对项。本轮只生成报告，不生成或应用图件。

方案必须引用本轮清单中的素材。参数化配方在规划阶段校验并补齐实际参数；保存的手工组件不能重新生成或改变配方参数。每张参考图都须有采用 / 舍弃说明，采用的图片还须明确关联到方案分区。需要确认科学含义时显示待补充问题，不能采用。

点“采用绘图方案”只恢复当前会话中已完成方案的输入快照，填入下一轮要求，不调用模型、不改画布。再次发送才生成待审候选。程序恢复规划时的原生素材和参考图片，当前素材库删除或修改原组件不会改变这些冻结输入。采用后更改画布或参考图会阻止发送，须还原或重新规划。

生成阶段校验全图容器样式、配色、根容器填充，以及计划新插入的素材及其参数数量。不允许漏用、改变配方参数或额外插入清单素材。根容器标题由程序写入已采用方案的标题，相同的图件标题不重复显示。字体排布、局部语义配色、图示的科学含义、注释质量和全部布局关系仍需人审阅，程序检查不能证明完全遵循方案或达到论文质量。

第三十五批增加组件实例标识与可审阅的默认主题色：同一素材可按实例选择不同色槽，生成后由程序绑定，保留手工颜色、显式色槽和原生结构。全图默认色也可随风格保存，详见[组件色槽绑定](component-color-bindings.md)。旧的无实例标识方案需重新规划。

第三十六批增加组件 `colorMap`，可逐一映射真实来源色槽，目标采用方案配色。它与该组件的默认色 `colorIndex` 互斥，生成时由程序从已采用方案注入，保留固定 RGB；完整规则与人工预览见[多色角色映射](color-mapping.md)。

程序保存来源记录到图件 `compositionPlans`，模型不能伪造或删除。工程、组件捕获、缩放和原生 SVG 元数据往返保持；根容器属性可移除记录并撤销。最多保留四份。记录是规划来源，实际图片采用和素材复用另有报告。

刷新后恢复历史方案报告，但不会自动采用。重新采用需要当前本地服务中可用的原运行，且画布与规划时一致；服务会话内存与运行图片受现有保留上限约束。工程中的方案记录保留文字与来源信息，不包含一套永久独立的图片 / 素材服务。

规划入口与数据附件、重建 / 视觉审阅任务互斥。选择数据或重建任务会清除已采用方案。接口新增 `intent: "plan"` 与 `compositionPlanRunId`；后者不能混入新清单或新图片。主要实现在 `core/compositionPlanContract.ts`、`core/compositionPlan.ts`、Harness 服务与 `components/harness/CompositionPlanView.vue`。

## 数据图：从研究问题选型

数据导入新增“图要回答什么问题？”，例如“比较各模型准确率与推理延迟的取舍，标明模型名称”。可选填最多 2,000 字，随固定数据附件进入列概况、提示和推荐报告，导入后带入助手要求。编辑附件时恢复目标，历史报告保留导入时的原文；本轮明确修改目标时提示模型以本轮要求为准并解释变化。

无需由人先指定图型。模型结合目标、原始列、数值含义及图片样式，选择折线、分组柱状、散点、热图或箱线；不足以确定选型时提问，长表需要展开时先提出可审阅预览。观测值和固定统计继续由程序从原表读取，模型不能提供替代数值。完整入口与容量见[数据可视化选型](chart-selection.md)。未整理的普通图表尚未将整份原表 / 研究目标作为独立永久素材服务保存；报告保留在当前服务历史。

## 复合主图编排（第八十六批）

新方案提示要求按叙事选择结构，为每区给出 `design={role,structure,rationale,emphasis,frame}`，并区分连接类型。全图一个主视觉，按内容组合经典结构；简单图允许单一结构，不能按结构种类计数来评价质量。`frame` 使用根内容区的归一化坐标，ID 对应 stage 的实际直接子容器，分区不重叠；实例须归属指定区，可直接以本区实例作为分区框。

候选校验新增位置／尺寸 2px 容差、可见内容及组件归属；数据流／反馈检查跨区连接的箭头方向，局部对应检查无箭头绑定路径。对照与包含关系的实际科学含义仍由人审阅。旧的文字方案继续可读，不强制迁移。布局检查仅在方案候选生成／应用时执行，保存记录不作为后续每次编辑的活动布局约束。完整研究与可编辑示例见[论文主图编排](../research/2026-10-31-paper-composition.md)。

## 结构适配与自动候选（第八十七批）

原生素材目录的 `compositionUse` 描述结构族、适用的方案角色、内容匹配条件和误用边界。保存的手改资产若带原配方，仅提供来源配方的指导，必须看实际保存内容。新方案提示的 JSON 示例现在也含完整 `design`，与分区约束一致。

仅自动推荐在识别到主图／复合意图时做同族软降权：正匹配按原分数除以 `1 + 0.8 × 已选同族数` 依次选择，原始相关分数不改；没有正匹配的项排在匹配项之后，补缺时先考虑未出现族。原生配方按结构族，基础图元按结构／种类，个人资产各自独立，最多六项且按键去重。手选和普通查询沿用原路径。这个启发式增加互补候选的机会，不判断科学兼容或证明最佳组合；模型应按内容舍弃不适合的候选。

U-Net 的复制／裁剪拼接、FPN 的逐层相加、残差的捷径相加应分别说明；在结构上把残差块放进 U-Net 会改变原架构，不能仅因同在清单而自动改造。实例与局部解释的关系见[跳连编排研究](../research/2026-10-31-skip-composition.md)。

## 新就绪方案必须有实际版面（第八十八批）

`parseCompositionPlanResponse` 对新 ready 结果默认要求每个分区都有 `design`，缺失则整份规划失败，不可采用；`design` 中已有的主视觉、分区不重叠和连接类型检查继续生效。needs-input 可以先列出科学含义问题，无需猜版面。服务沿用默认严格策略，模型 JSON 无法覆盖它。

历史存储的 `compositionRecordSchema` 继续支持旧文字方案。低层解析器的 `layoutPolicy:'legacy'` 只供显式兼容读取／检查使用，正常服务不启用；已有单元场景以此保留历史契约验证。原 CLI 规划与绘图夹具现在产生真实分区框和实例归属，缺失设计的 ready 结果在服务测试中被拒绝。未增加 UI 流程或重复 CLI 适配器矩阵。

路由主图示例包含阶段概览、专家银行与控制／数据路径、共享线型图例及真实选区快照，见[图聚合与路由研究](../research/2026-10-31-graph-routing.md)。


## 参数迁移与近期主图编排

`parameter-transfer` 区别于样本数据流：实际跨区 edge／双端绑定 path 必须为可见、方向正确、单向的虚线；逆向、实线、双向或隐藏路径拒绝。程序核对连接外观和端点，不证明两模块的参数张量兼容。规划与生成提示均需明确迁移哪些参数、哪些训练专用模块不部署。

分区结构新增 `temporal-memory` 和 `alternating-attention`。规划器提供已核对录用来源的四种叙事策略，包含适配条件、跨结构编排和所需用户信息：SAM 2 任务／模型／数据、VGGT 共享核心与分型输出、DUSt3R 公共表示／任务树／证据，以及 Transfusion／Show-o 混合位置／许可解释／实际生成机制。策略属于选择依据，没有强制模块清单或固定坐标；缺少数据引擎、结果图或真实关系时不能补造。见[近期主图研究](../research/2026-10-31-recent-mainfigures.md)。


视觉设计原则由 `scientificFigureDesign` 同时提供给规划与绘制阶段。方案需说明第一眼重点、不同对象的语义轮廓及无需外框的区域，生成阶段看到同一规则。当前规则属于有依据的生成指导和原生样例实现，没有基于节点数、颜色数或无截断自动打审美分。
