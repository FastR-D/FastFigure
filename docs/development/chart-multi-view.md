# 数据多视图选型

助手可以针对同一份导入附件提出 2–4 个互补视图，由程序编译为带 `(a) / (b)` 标号的原生组合图。例如同时回答“模型延迟与准确率如何取舍”和“各模型的内存用量如何比较”，不把不同单位机械放进同一个纵轴。

## 操作与报告

在左侧助手导入 CSV / TSV，填写表达目标、单位、数据身份和明确的误差含义后发送。无需先指定图型；单图能表达清楚时仍优先单图，含义或支持能力不足时先提问。多视图结果逐项显示图型、选择理由、映射列、本图未使用列、实际坐标 / 色标 / 箱线统计、误差归属、备选和局限。每个视图共用本轮冻结附件，报告保留导入时的表达目标。

候选不会自动应用。应用替换当前图形并可单步撤销；各图保存在独立的数据图容器中，能继续改数据、调整文字、移动面板、捕获素材并通过工程 / SVG 元数据保存。默认使用独立坐标与图例。现可显式请求 sharedY、sharedLegend、sharedColorbar 与 alignPlots，分别由程序统一纵轴范围、生成共享图例、统一热图数值色阶并共享色标、对齐现有网格内的绘图区；详见[统一纵轴](shared-yaxis.md)、[共享图例](shared-legend.md)及[绘图区对齐](plot-alignment.md)。缩小后的小字仍需按出版尺寸核对，界面提供小于 8 个画布单位的提示。

## 编译约束

新增 `multi-view` 分支，原有 `ready`、`prepare`、`needs-input` 保持各自职责：

```json
{
  "status": "multi-view",
  "title": "组合图标题",
  "columns": 2,
  "gap": 24,
  "views": [
    { "caption": "简短说明", "chart": "完整的 ready 推荐对象" },
    { "caption": "另一项说明", "chart": "完整的 ready 推荐对象" }
  ],
  "reason": "为什么需要互补视图",
  "alternatives": [],
  "cautions": []
}
```

其中 `chart` 实际必须是严格的单图 `ready` 对象，上例用字符串缩写示意。不能嵌套多视图、整理或待确认分支；模型只能选择字段、图型和已支持样式，不提供数据、图元、归一化、过滤、聚合或统计结果。列引用、真实数值、缺失 X、误差端点、原始观测声明和坐标范围沿用单图校验。

每张图独立读取全部原始行，重复 X 和缺失保持；不会因为一个视图缺失就删除另一视图中的同一模型。已经明确采用的长表附件，逐图沿用同一个原表 / 展开映射，不暗中再次整理。原始箱线摘要仍由固定规则计算。已应用图件保存选择的数据和来源声明；没有绘制的其他原始列尚未形成持久共享数据源，完整原表仍需另存。

附件误差声明与本图误差分开报告。点线 / 柱状只有实际选择了 `errorColumn` 才获得该声明和误差线；没有误差列的内存等指标不会继承准确率的 SE。修正也用于单图。热图 / 箱线仍拒绝忽略非空的附件误差声明，需先确认数据含义。

所有视图先独立编译，确认总图元不超过 240，再在程序私有草稿中展开和统一编排。临时重叠不会出现在候选中；只返回最终合法 FigureIR。沿用 21 个容器、六层嵌套、标题范围与几何限制，任一视图、整体容量或排版失败则整次拒绝，不删行、删点、删视图或保留部分候选。选择理由由模型提供，程序不能证明单位推断或图型选择最优。

## 验证与实际调用

复用现有选图文件，增加三个不同风险场景：多单位视图 / 逐图误差 / 原生保存；已确认长表的全部观测与固定箱线统计；单项失败和总图元容量的整次拒绝。双 CLI 原协议场景验证图片、冻结输入、多视图报告、非法嵌套数据与旧候选保留。原数据 UI 流程增加组合推荐、逐图报告、应用 / 撤销 / 重做与刷新，仍为 40 个核心 / 服务文件、五个 UI 文件和四条 1920×1080 流程。

开发 UI 首轮误把原生 `summary` 当作指定按钮查找，第二轮在未保存的重做后刷新触发工程保护；修正了操作脚本，没有绕过产品的保存保护。失败日志与截图保留在 `test-results/chart-multi-view-development-v1/`。最终 Lint、类型 / 构建与四条 UI 流程通过，UI 30.410 秒；核心检查为 517 项。

一次真实 Codex 调用使用 4 行 × 5 列自制表和既有自制样式 PNG，没有先指定散点或柱状。CLI `0.165.0`、使用本机默认模型配置，具体模型身份未报告。运行 `2f32bbdc-2dc7-45e0-aaa3-fd3e99dc6a1c` 在 45.012 秒返回两视图：带模型名和 SE 的延迟 / 准确率散点，以及独立零基线的模型内存柱状。79 原生图元、五个容器；重复延迟、缺失准确率、C 的内存值与示例标记保持，内存图没有借用 SE。结果保持待审阅，没有应用到用户正在使用的工程。

完整输入、实际附图、提示、原响应、原生候选、PNG、源码快照和指标在 `test-results/chart-multi-view-live-codex-v1/`。随后仅离线回放同一原响应，在独立服务 / 页面核对逐图说明、实际原生节点一致、应用 / 撤销 / 重做与保存恢复，零追加模型调用、零运行时错误；记录在其 `ui-offline-replay/`。这是一例开发验证，不是独立论文质量或最优选图评测。
