# 原生缩放点积注意力

第四十二批增加 `recipe:scaled-attention`。紧凑 attention 预设继续保留；新配方提供可展开、可复用的矩阵与运算关系，避免把注意力表示为一个文字框。

## 结构与来源

按 [Attention Is All You Need §3.2.1 / §3.2.3](https://arxiv.org/html/1706.03762v7) 核对计算顺序，原生几何由程序独立构造，并非论文原图描摹：

`Q × Kᵀ → ÷ √dₖ → [可选 + M] → Softmax（沿键）→ A × V → Y`

Q、Kᵀ、V、A 和 Y 各自是自由组合，框线、网格、标题与符号维度可独立编辑；整体移动矩阵组会一起移动。网格线绑定矩阵外框，单独调整外框时端点跟随。圆形乘法、缩放和 Softmax 使用原生图元，运算间连接为引用节点的语义边。标题、公式、简洁注释与完整来源随组件捕获、重插、缩放及原生 SVG 保留。

这是一张单头计算示意，不包括输入投影、多头拼接、残差或 LayerNorm。当前形状标注采用等长查询 / 键序列的 `n`；不是任意不同长度跨注意力的完整表示。`dₖ` 与 `dᵥ` 是独立符号，相同视觉格数不表示二者相等。

因果模式先在 Softmax 前加入 M。Q 与 K 须共享序列位置顺序；A 的上三角斜线表示被屏蔽后为零的权重，其余单元不显示任何数值。它不是从真实输入算出的注意力热图，也没有为用户虚构权重。

## 使用

左侧“组件 → 参数化组合 → 缩放点积注意力”配置并预览，插入当前容器或新建图件。尺寸分别为 880×510、980×510；空间不足时可显式等比缩小或新建图件，不覆盖现有对象。

| 参数 | 选项 | 含义 |
| --- | --- | --- |
| `tokens` | 3–6，默认 4 | 示意序列方向格数，不是实际序列长度 |
| `channels` | 2–5，默认 4 | 示意通道方向格数，不指定实际维度 |
| `mask` | none / causal，默认 none | 无掩码或同序列因果掩码 |
| `details` | show / hide，默认 show | 显示或隐藏符号维度；示意说明始终保留 |

命名接口：

| 标识 | 输入约定 |
| --- | --- |
| `query-in` | Q |
| `key-transpose-in` | 已转置的 Kᵀ，不能把原始 K 直接当成该输入 |
| `values-in` | V |
| `attention-out` | 输出 Y |

按内容把 Q / K / V 与外部特征相连之前，需要由作者确认维度、转置与科学含义。接口不显示在论文导出画面，输入输出短线仍保留。

助手自动 / 手动检索、绘图方案、普通实例编译和混合重建图谱使用同一配方与参数清单。目录另提供 `attentionSemantics`，说明单头范围、转置输入、掩码位置与示意计数，避免模型根据图格猜实际维度。可按源别名改标题与注释；参数只在生成阶段生效，已保存个人组件保留手工编辑，不自动回到配方重生成。

Q / Kᵀ / V / A / Y 采用不同主题色槽，支持现有配色和多角色映射。换色不改变计算顺序、格数或接口；颜色只辅助识别。SVG 保留原生文字、路径及工程元数据，draw.io 的自由路径沿用独立 SVG 对象，外部往返尚待验证。PPTX 继续暂缓。

## 验证

现有资产检查覆盖最小 / 默认 / 最大格数、两种掩码、隐藏维度、计算连接顺序、明确的 Kᵀ 接口、斜线掩码随外框移动、捕获缩放重插与原生实例编译。上述六种配置的连接无阻塞，原生文字检查没有截断项；这不代替实际字体和科学内容审阅。

现有编辑流程加入配置因果模式、改变示意格数和插入的验收。UI 仍为五个文件、四条 1920×1080 流程，没有添加逐按钮脚本。素材目录测试移除写死素材总数的断言，改为核对所有公开种子 / 配方均可被检索和展开。

后续测试清理已将默认浏览器回归收敛为一类代表配方的配置流程，不再逐配方重复；注意力拓扑、掩码与接口仍由现有核心场景检查。当前维护口径见[开发与验收约定](testing.md)。

最终 Lint、类型、522 项核心 / 服务检查、构建与四条 1920×1080 UI 流程通过，UI 用时 20.871 秒。既有 Vite 扩展名导入和包体积提示仍在，未扩大本批范围处理。

## 从真实放置失败补充显式 fit

一次本机 Codex 实际调用选择了正确配方、`tokens=4`、`channels=4`、`mask=causal` 和 `details=show`，并返回了中文标题、明确的 Kᵀ 输入与掩码公式。运行 `2cbdc587-6f69-4a04-865a-28bac0dca21d` 用时 58.26 秒，具体模型身份未报告。它给宽 980 的组件指定 `x=60, scale=1`，超过宽 1000 的父容器内容区，整份候选被拒绝。原运行仍为失败，用户画布保持。

据此为普通实例增加 `fit={width,height}`：以实例 `x/y` 为左上角声明一个完整处于父容器内容区的区域，先展开实际参数 / 图表设置，再计算 `min(width/实际宽, height/实际高)`。它与 `scale` 互斥，不变形、不挪动其他对象，保留左上角，右 / 下方可留白。缩放仍限定 0.1–4，并继续执行容量、几何和实际对象碰撞限制；不因 fit 而自动接受不可读的字形。

复用报告显示声明区域和实际比例。现有目录检查覆盖配置后的真实尺寸、越界区域、比例下限、互斥和碰撞的原子拒绝；现有双 CLI 张量用例改用 fit，核对请求区域、计算比例、原生接口与引线保持，没有另建脚本。

仅把保存响应中该实例的 `scale:1` 改成显式 `fit:{width:880,height:500}` 后，零追加模型调用离线编译：比例 `0.8979591836734694`，69 个原生图元、9 条内部语义边、6 个斜线掩码及四个命名接口。保留模型原有标签覆写；逐节点几何最大数值误差约 `1.14e-13`，原生拓扑和绑定保持，连线全部 clear，20 个文字字段无截断报告，浏览器运行时错误为零。已查看实际候选、默认配方与桌面截图。

产物在 `test-results/scaled-attention-live-codex-v1/`：原输入、提示、响应、失败运行和相关源码快照保持；`offline-fit-v2/` 保存明确的人工修正、候选工程 / SVG / PNG / 捕获组件、源码快照和核对记录。第一次离线渲染脚本因 CommonJS 浏览器包导入方式失败，记录留在 `offline-fit-v1/`；修正验证脚本后重做离线核对，未追加模型调用。

这是人工修改放置契约后的离线候选，不是原响应不变的重放，也不是新 fit 提示下真实模型重跑成功。模型候选仍有根标题与组件标题重复、中英注释混排等待审问题；本例不证明论文质量、科学正确性或 RSI 效果。结果没有应用到用户工程或晋升素材库。
