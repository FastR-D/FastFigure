# 整理素材检索信息

第四十八批增加名称、说明、标签与补充引用的编辑，供本机库和批量导入共用。信息整理是可追溯的派生操作：图形、图中文字、命名接口、配方和已有来源保持，变化后的完整组件生成新的内容指纹。

## 本机素材

在本机素材详情点击“整理检索信息”，填写检索名称、说明、标签，可补充多条引用；已有来源显示在下方，不被覆盖。名称最多 100 字、说明 300 字，去重后的标签最多 12 个且各不超过 30 字，来源名称 / 引用须成对填写，来源总数仍最多 12 条。

“另存整理后的新快照”先核对原组件 SHA，再从未缩放的原快照准备新版本。当前“插入缩放”不参与整理；检索名称也不替换图中标题或节点标签。保持原组件 ID / 创建时间，更新版本时间，在派生记录中追加 `snapshot-<原 SHA>`。旧快照继续存在，库中同 ID 的不同版本分别保留。

未改变规范检索信息、或只重复已有引用时不创建新版本。来源链仍受 16 项上限约束，满时拒绝，不截断原证据。保存准备完成后冻结完整请求；回执丢失时“重试保存同一快照”不会换时间或新建另一个内容指纹。也可明确重新编辑草稿，但这不会回滚可能已经提交的版本。

详情的“派生详情”显示来源名称、修订和完整标识。`snapshot-` 来源可尝试打开本机原快照，读取时重验 SHA；便携文件引用的快照可能不在当前库中，读取失败时保留当前详情与来源记录。

## 批量导入

每项预览中可展开“整理检索信息”，编辑后点击“应用检索信息”。选中项尚有未应用修改时，入库按钮会阻止提交；可恢复原始信息。适用字段与本机版本共用，不修改图中文字。

每次准备从该文件第一次解析的原始组件派生，追加 `source-<原规范组件 SHA>`，不把它冒充已经存在的本机库存 SHA。原始字节 SHA 与入库资产 SHA 继续分别显示。入库记录增加原规范组件 SHA、是否整理、未应用状态和首次提交时间，不导出输入中的未应用字段草稿。

在首次提交前可继续整理同一个草稿，版本时间固定为该草稿首次准备时间。首次提交后，字段保持冻结；失败项可重试同一内容，已存项可在详情再整理新版本。用户关闭 / 清空页面队列的语义沿用[批量导入](component-batch-import.md)。

原始解析缓存与整理后的 payload 分开。添加相同源文件时复用原解析结果，不继承另一项的标签、引用或改名；当前入库内容实际相同才标为重复。这样既保留文件恢复身份，也允许同时保存原始与已整理版本。

## 依据与范围

新增引用仅为填写者提供的说明，不生成论文、作者、许可或科学关系，也不表示来源已获独立核对。名称与标签会进入既有文字索引和助手候选目录；没有据此自动批准素材、训练模型、归档旧版本或保证检索相关性。

第五十批可在详情明确[归档或恢复](component-archive.md)任一版本；整理信息仍不会自动归档父快照。归档父版本保持原 SHA，新版本的派生来源仍可打开它。

复用原有存储接口，没有原地更新 / 删除快照的接口。派生结果与原文件都符合相同的组件、容量和来源预算。图形的编辑继续在原生画布完成，信息整理不调用图表重生成或模型。

## 验证

现有持久库检查增加一个完整场景：验证父指纹、原证据、原 ID / 创建时间及完整图形保持、新词索引、无操作去重、文件来源指纹、错误父引用和来源链容量拒绝。

原助手 UI 流程增加批量信息应用、原尺寸信息派生、提交后丢回执重试、图形 / 来源保持、新标签检索和打开父快照。UI 仍为五个文件、四条 1920×1080 流程。最终 Lint、类型、531 项核心 / 服务检查、构建与四流程通过，UI 24.756 秒；既有 Vite 导入 / 包体积和 SQLite 提示保持。

另在上一批开发库的独立副本和全新页面操作：

- 对已有的 80 图元 / 九边素材先设置 65% 插入缩放，再整理信息。新快照完整图形（包括标签、几何、绑定、接口和子组件参数）与原快照逐项相同，旧资产 / 创建时间 / 来源保持，追加父快照记录；检索与文字召回命中新标签。
- 批量整理一份原生 JSON，再添加相同原文件；后者仍是原始组件，没有继承先前编辑。整理版与原始版各自保持身份，提交过的字段冻结，记录可导出。
- 三次入库请求后，独立副本由两份素材变为四份；其中一项是旧内容精确重复，没有增加快照。当前工程保持，零真实模型调用、零浏览器运行时错误。

证据在 `test-results/component-metadata-ui-v1/`，含原 / 新快照、批量记录、源代码、检索结果、SQLite、实际表单 / 搜索截图与 `metrics.json`。已查看实际表单。补充信息由开发代理在既有自制素材上填写，不是独立人工标注、真实论文质量或 RSI 结论；该独立操作早于最后补充的父快照按钮，按钮另由最终默认 UI 流程覆盖。
