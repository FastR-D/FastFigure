# 本机持久素材库

第四十三批增加本机单用户的组件快照服务。浏览器“我的组件”继续保存最多 50 项工作组件；独立本机库承担长期积累，开发服务、预览服务和新浏览器页面可使用同一目录。

## 使用

在配方、论文模板或我的组件详情点击“存入本机素材库”。程序冻结当前可编辑组件，以真实字体渲染缩略图，再保存快照；不改写画布、不自动批准 AI 候选。

第五十六批可在本机库点击“从当前图件采集”，或在助手候选点击“从候选图采集素材”。选择局部对象、容器或描摹分区后，先准备原生预览，再加入待入库队列，核对后明确保存。支持连续准备多份片段，导出完整来源快照并按指纹追溯，详见[局部采集](component-capture.md)。

第四十七批增加“批量导入 JSON / SVG”：多文件预览、逐项来源 / 指纹与解析提示、暂停 / 继续、部分失败重试和入库记录导出。每批最多 50 个、50 MB，单文件 2 MB；原生 JSON 保留完整身份，SVG 沿用受限原生解析器。详见[批量导入](component-batch-import.md)。

第四十八批可在素材详情“整理检索信息”，补充名称 / 说明 / 标签 / 引用并另存新快照；保持图形和已有证据，旧版本可由派生详情按 SHA 打开。批量队列共用相同字段，提交后保持冻结。详见[信息整理与派生语义](component-metadata.md)。

第五十批可手工归档 / 恢复快照，列表提供“当前素材 / 已归档 / 全部版本”。默认检索和本机库新任务自动召回排除归档项，原指纹、导出、派生追溯及已冻结任务保持。归档不释放容量；重复入库不会自动恢复。详见[归档与恢复](component-archive.md)。

第五十一批增加“素材反馈记录”，按素材名 / 绘图要求和最新判断查找，查看冻结图元与改判链，导出单项 JSON 或筛选反馈集 JSONL。反馈表独立于素材快照计数，不自动发布素材；保存的样本不依赖原会话继续存在。详见[反馈与存储边界](retrieval-feedback.md)。

左侧“组件 → 本机素材库”按名称、说明、标签、来源引用、原组件 ID 或快照 SHA 检索。最多八个空格分隔的词须同时命中；文字大小写归一，没有 embedding 或 CLIP。每页显示 12 项，点击卡片读取实际原生预览、来源、接口与完整指纹。

直接插入或新建图件不占浏览器名额，沿用缩放、空间 / 碰撞检查及撤销。“取为我的组件”保存工作副本；同 ID 不同内容创建副本，保留手工编辑。“用于助手”取回一份工作组件并选为本轮参考，不自动发送；可再选其他组件，每轮最多六项。发送时冻结完整结构，库变化不影响已发送任务。

实际插入和工作副本追加 `snapshot-<SHA-256>` 派生记录，随图件、再采集和原生 SVG 保留，不携带本机目录路径。沿用 16 项来源链预算，满时明确拒绝，不截断来源。“导出原快照”下载未缩放、未添加派生记录的原组件，指纹可核对，来源链满时仍可备份。

## 存储

默认目录为 `~/.local/share/fastfigure/components/`，数据库为 `components.sqlite`。可在启动前配置：

```bash
FASTFIGURE_LIBRARY_DIR=/path/to/figure-library pnpm dev
```

同一用户的 dev / preview 默认共享目录；接口首次使用才创建目录和打开数据库。静态 `dist` 不含此服务。使用 Node 内置 SQLite，没有新增 pnpm 数据库依赖；当前 Node 22.22.2 实测通过，项目要求的 Node 22.18+ 无需额外启动标志。Node 22 仍输出实验特性提示，见 [Node SQLite 文档](https://nodejs.org/download/release/latest-jod/docs/api/sqlite.html)。

每个规范组件最多 2 MB，库容量为 10,000 项 / 2,000,000,000 字节的组件正文。索引、缩略图和 SQLite 日志另占磁盘；这不是整个目录的磁盘限额，也不是已验证的万条性能。缩略图为 PNG / WebP，最多 80,000 字符、640×480；客户端当前生成 360×220 预览。

逐项导出不需要停服务。备份整个库时，先停止使用该目录的 dev / preview，再复制整个目录；运行中不要只复制主数据库而遗漏 WAL。归档状态与正文保存在同一数据库的独立表中；没有永久删除、账号或多机同步。容量不足时先备份，再为服务选择其他目录，不自动清理旧快照。

## 身份与一致性

SHA-256 基于键顺序稳定、完整规范化的组件 JSON，包括原 ID、版本时间、图元、来源、AI 草稿标记和派生记录。相同快照重复提交返回原记录；内容或元数据变化生成另一条，即使原组件 ID 相同也不覆盖旧版本。这是精确去重，不是视觉去重。

正文、元数据和检索文本在同一个 SQLite 立即事务中提交，使用 WAL；两个句柄可读取彼此提交的数据。容量失败回滚，读取重新验证正文指纹；损坏记录及重复提交命中的损坏内容拒绝，不自动修复原证据。

缩略图从冻结组件生成，并附组件指纹。服务检查关联指纹和受限栅格图片头，不将预览当作科学或视觉质量认证；详情继续读取原生结构核对指纹。

## 本机接口

接口前缀为 `/api/component-library`，检查本机 Host / 同源 Origin，不接收文件路径或 SQL。正文最多 2.2 MB，使用 `application/json`；查询使用绑定参数。

| 方法 | 路径 | 结果 |
| --- | --- | --- |
| GET | `/status` | 目录、总 / 当前 / 归档数量、正文大小、容量限制 |
| GET | `/snapshots?q=&scope=active&offset=0&limit=12` | 当前 / archived / all 范围分页，每页最多 24 项 |
| POST | `/snapshots` | `{asset,thumbnail?:{assetSha256,dataUrl}}`；新增 201，精确重复 200 |
| GET | `/snapshots/:sha256` | 原组件与元数据，验证失败不返回可用快照 |
| POST | `/snapshots/:sha256/state` | `{archived:boolean}`，改变独立状态，不改原内容或 SHA |

素材由人明确入库，不含模型直接写库或自动发布；用户声明的论文来源不代表许可或质量审核。

## 验证

新增一个服务检查文件、三项存储场景：不可变版本 / 去重 / 多句柄与重启 / 来源绑定，HTTP 容量 / 同源 / 图片关联 / 原子拒绝，以及损坏检测。UI 仍为五个文件、四条 1920×1080 流程；助手流程验证存入本机库、移除浏览器副本、刷新取回、携带快照来源规划。默认 UI 库使用临时目录并清理，不接触用户素材。

Lint、类型、525 项核心 / 服务检查、构建与最终四条桌面流程通过，最新 UI 用时 21.131 秒。既有扩展名导入和包体积提示仍在；本批 Node 22 SQLite 的实验提示已在运行约束中说明。

另外用缩放注意力、透视张量栈两个自制配方，在独立端口和目录实测保存、重复返回、服务关闭重启、全新浏览器来源、论文来源检索、原文件导出指纹、插入图件 / SVG 追溯及助手工作副本。本轮零模型调用、零浏览器运行时错误；实际界面已查看。产物在 `test-results/component-library-ui-v1/`，包含独立数据库、原快照、图件 / SVG / PNG、源码快照与 `metrics.json`。

这验证本机存取链路，没有测试万条素材延迟、真实论文批量采集、模型检索质量或 RSI。第四十四批已增加[普通绘图与规划的库级文字自动召回](repository-recall.md)，第四十六批增加[助手逐项筛选](repository-selection.md)，第四十七批增加[JSON / SVG 批量导入](component-batch-import.md)，第五十批增加[手工归档与恢复](component-archive.md)；图像检索、更多输入格式和来源管理继续开发。

## 相同图形核对

完整快照仍精确去重。批量积累素材时另有原生内容索引，可检查改内部 ID、重新采集或来源不同的相同图元内容，查看归档 / 当前候选并明确保留独立快照；不会改写旧快照或合并来源。范围与实际验证见[相同原生图形核对](component-content.md)。
