# 多参考、原生素材与风格的真实组合验证

第三十四批，2026-10-30。用三张自制参考图、一份原生 MLP 组件和一份已保存风格，完成一次真实的“先规划 → 审阅后采用 → 生成待审候选”。本轮不是来自真实论文的质量评测。

## 输入与实际调用

三图分别只承担横向构图、柔和配色与留白、MLP 结构语义。请求是“输入特征向量 → 给定 MLP 分类头 → 两个类别分数”，没有 softmax、训练、损失或实验数值。原生素材含 3–3–3–2 神经元、24 条内部直线和两个命名接口；风格为 Quiet paper，手绘轮廓、Publication Soft、MiSans。

开发助手读取方案后，显式输入与规划运行匹配的生成命令；不是人类受试者审阅实验。规划没有生成图体，生成结果保持待审，没有应用到用户工程。两轮实际图片字节、顺序及 SHA-256 均与源输入一致，原组件和输入图件保持不变。

输出目录为 `test-results/composition-style-live-codex-v1/`：原始提示、输出、事件与报告、方案和采用记录、输入图片、风格与组件快照、源码指纹、原始候选和捕获后的组件均保留。`metrics.json` 验证 11 个神经元、24 条内部边、两个命名接口及两条外部连接，节点种类、标签、字体与等比几何保持，风格和方案来源进入捕获素材。

## 实际发现与修正

原始结果暴露了三个问题：手绘渲染默认把完整画板铺成斜线底纹；空白模板的根标题仍是 Method overview；方案描述处理中区为蓝色，但复用的 MLP 仍保留原素材的青绿色。

已修正前两项。容器属性新增“容器填充”，风格编辑新增“风格容器填充”，可选择纯色底、斜线底纹或透明。手绘轮廓默认配白底，底纹须显式选择。选择随风格和绘图方案保存，生成时核对根容器填充；未填写时按纯色底解释。底纹目前在手绘皮肤下渲染，其他皮肤保留选择。透明和自定义底色 / 描边可用于原生容器；应用风格时保留数据图表自己的容器格式。

采用方案后的根标题由程序写入方案标题。图件标题与根标题相同时，渲染器只显示一次。另修复选择“先规划”后新建会话导致任务静默回到绘图的问题；数据、重建和候选修复任务仍明确切换到对应绘图通道。方案报告改用素材名、分区名和参数中文标签，便于实际审阅。

修正没有追加模型调用。同一份原始候选经当前规则重新渲染，保存在 `render-revision-v1/`；原始候选与图片保留。修订只改根容器标题与白底，所有节点、边、内层容器和来源记录保持，详见 `revision.json` 与修订源码快照。人工查看修订图片确认底纹消除、标题正确且结构可读；程序文字检查为零项，26 条路线均未被判定受阻。这些检查不覆盖真实字形测量、交叉线优化或科学正确性。

局部语义配色仍未实现完整遵循：MLP 保留青绿色，与方案的蓝色处理中区不符。风格中的文字说明目前是模型指导，不是对每个局部对象的强制映射；不能据此宣称样式完全符合方案或达到论文质量。draw.io 输出已加入填充和描边设置，手绘底纹采用相应原生样式参数，外部编辑器外观与往返仍待验证。

后续第三十五批新增[组件默认色绑定](component-color-bindings.md)，用同一开发要求完成两次新的真实调用，MLP 默认色问题已修正；此处保留第三十四批的原始结果与限制记录。手工颜色、显式色槽与内层覆盖依然优先，完整局部角色映射尚未实现。

## 验证与复验

Lint、类型检查、498 项核心 / 服务检查和生产构建通过。界面仍只验收 1920×1080 的四条核心流程，测试仍为 `tests/ui/` 中五个文件。填充、规划偏好、数据任务切换与标题修复加入现有流程或已有测试，不另建逐控件脚本。

真实模型工具继续隔离在 `experiments/`。复验使用现有脚本和全新输出目录，不纳入默认测试；`--plan` 在规划完成后等待检查，只有输入其输出的匹配命令才进行第二次调用。`--style` 接受导出的 `fastfigure.style` 文件。

```bash
node experiments/multi-reference-live.mjs --output test-results/composition-style-live-codex-v2 --plan --style 'test-results/style-assets-targeted/Quiet paper.fastfigure-style.json' --timeout 360
```

该例用于开发调试，没有留出集、独立人工质量评分或成功率结论，也未实现自动 RSI。后续需让颜色角色与可审阅对象映射绑定，再以更多自制与真实论文样例评估布局、科学含义和风格遵循。
