# 原生文字检查与模型反馈

2026-10-29，第卅一批。画布、候选和导出窗口可核对原生文字的排版；普通绘图助手收到当前图件的程序检查结果，候选完成后由程序重算并保留到运行记录。

## 使用

画布下方“检查文字”打开当前图件检查。报告显示原文、当前排版、所需 / 允许行数、字号和可用区域，可定位对应节点，在属性栏调整框体、边距或字号后重新核对。检查本身不修改图件、不调用模型；人工改动仍可撤销。长报告在弹窗内容区滚动，底部操作保持可见。

助手候选的“生成前 / 候选结果”预览各有当前视图的文字检查；点击定位只高亮该预览中的节点，不修改画布。消息里的“生成时文字检查”是当次服务生成并保存的记录。切换历史、刷新、应用或撤销不重写旧记录；当前预览检查按当前渲染实现重新计算。导出窗口也提供相同检查，可返回定位，也可按原有流程直接导出。

检查分三类：

| 原因 | 含义 |
| --- | --- |
| `line-limit` | 实际渲染的换行结果超过行数限制，已经用省略号替代部分内容 |
| `width` | 与换行算法共用的宽度估算显示当前文字行放不进可用区域 |
| `height` | 用字号和行距估算，已显示文字所需高度超过可用区域 |

原文自带“…”不会被当作截断。主标签、注释和结构标签使用独立字段，结构标签沿用可编辑的 `structure:N` 标识。报告尺寸为图件坐标单位，组件缩放后同步换算。

这里不测量实际字体字形，不检查遮挡、容器标题、科学内容或出版规范；宽高提示可能需要人工复核。定位字形节点、不可见节点和未绘制的紧凑结构标签单独计数，不把这些内容说成“已检查”。“本轮规则未发现问题”仅表示这些规则没有发现问题。图片视觉审阅继续使用已有原图 / 候选流程。

## 实现与信任边界

`layoutWrappedText` 返回现有渲染行、所需行数、限制和截断状态；`wrapText` 保持原调用接口。普通标签、说明文字、结构标题 / 内部文字使用同一结果绘制，并在 SVG 文本上写入程序拥有的布局标记。`checkFigureText` 从当前原生对象重新生成这些标记，不信任导入 SVG 的任意 `data-*` 声明或模型返回的报告。

引擎为 `native-wrap-v1`。每个节点的可编辑字段归并为一项，详细报告最多 80 项，保留实际总数及省略数；普通提示中最多附 20 项。字宽沿用当前渲染器的字符估算，不额外宣称已测量字体族、字重、斜体或字距后的真实字形。检查不增删节点，不变更文字、样式、数据、位置或来源。

普通绘图提示的 `context.textCheck` 来自当前源图，任务固定的重建 / 图片审阅提示与数据选型提示不额外混入这份当前画布报告。模型可据此调整布局，不能返回一份自称已通过的 `textCheck`。服务在完成候选后从程序展开、校验后的图体重算，将结果放入 SSE、轮次和历史；无候选不生成该记录。普通、数据图和重建候选都可使用程序的最终检查，但覆盖范围仍受上文限制。

## 真实反馈修复样例

使用上一批已保存的自制双面板 MLP 原生图件，注入两个明确的布局缺陷：`saved-caption.height=24`，`recipe-caption.visual.padding=12`。原始文件保留，源图的两处注释均包含显式换行；程序报告恰好两项 `line-limit`，没有附带图片。

一次显式 Codex CLI 0.165.0 调用，使用配置默认模型，身份未报告，预算 240 秒。运行 `7eb8e466-2031-47af-aca2-67a2cf49a15f`，93.765 秒完成。模型将左注释高度从 24 调为 52，右注释高度从 44 调为 52、边距从 12 调为 2；只有这两处节点发生变化。

程序重算从 2 项降为 0 项，并核对原文、显式换行、字体字号、位置、其他样式、所有节点 / 容器、48 条连线、拓扑、命名接口与来源保持；全部路线仍 clear。浏览器渲染的两处注释各自显示完整两行，字号仍为 15，检查后人工查看 PNG。候选为 pending，没有自动重试或应用。

证据位于 `test-results/text-check-live-codex-v1/`：原始输入及缺陷声明、提示、源码快照 / 指纹、响应、运行 / 指标、前后检查、精确差异、候选和前后 PNG / 渲染文字。一次自制无图能力测试不证明独立视觉理解、论文图质量或统计正确；这是一轮有程序反馈的修复，不是自动 RSI 循环。
