# 批量导入本机素材

组件 → 本机素材库 → 批量导入本机素材，可同时准备组件 JSON、SVG 和 draw.io，逐项核对预览、来源与解析提示，再存入长期素材库；不经过浏览器 50 项工作组件缓存，也不改当前画布。

## 输入与预览

每批最多 50 项（draw.io 按页计数）、原文件合计 50 MB，单个原文件最多 2 MB。同一个多页文件只计算一次原文件字节。规范化的组件正文仍须满足现有 2 MB、240 图元、120 边和来源链预算。数量 / 总大小超限时不追加这一批文件；展开多页后超限则标记该占位项失败，可通过单图入口选页。单页转换失败只标记该项，其余页面继续。50 项是当前界限，不是已验证的满额性能保证。

- 原生 `fastfigure.component` JSON：保留原 ID、日期、结构、标签、来源和派生记录。只做现有契约规范化，不为入库改名或追加虚构来源，便于按完整组件 SHA 精确去重。工程 JSON 或导入记录不是组件文件。
- SVG：复用已有解析器，保留分组、文字、贝塞尔路径和文件 SHA，按整个文件准备；有 FastFigure 元数据时优先恢复原生结构。恢复图中原有标题，文件名只作为素材条目名称；单图入口的名称编辑也只修改检索名称。
- draw.io：读取压缩 / 原始 XML 及嵌入源数据的 SVG。多页文件按源顺序拆项，保留同一原文件 SHA 与独立的页序号 / 名称 / ID；原生文字、形状及绑定连线路径来自该页。页面支持边界见[矢量导入](svg-import.md#drawio-源素材)。
- 完整几何适配、曲线转换或元数据恢复等提示逐项显示。有提示和批内相同内容的条目默认不勾选，可先查看预览再选择。复杂源图需要选择页面或子图时，使用单图 SVG / draw.io 入口；预览过的子图可以“加入入库队列”，保留原文件 / 页面来源与转换提示。批量入口不自动丢弃超限子图，也不把不支持的效果当作已保留。

左侧文件列表显示状态，右侧只渲染当前项的原生预览，可核对节点 / 边、来源 / 派生和两种指纹：**原文件 SHA** 对应原始字节，**组件 SHA** 对应规范化组件。不同空白或属性顺序的 JSON 可以有不同文件 SHA、同一组件 SHA。

第四十八批可展开“整理检索信息”，在提交前编辑检索名称、说明、标签与补充引用；点击“应用检索信息”形成保留图形 / 原来源的新派生。未应用的选中项不能提交，首次提交后保持冻结。未整理时仍保留原文件身份；相同文件的原始解析缓存不继承其他行的编辑。细节见[信息整理](component-metadata.md)。

重复的同一矢量文件及页面在当前队列中复用第一次冻结的解析结果；相同字节但文件名不同，会分别保留文件名来源。同文件不同页不会误用另一页的缓存。清空或刷新后重新解析可能产生新的组件 ID / 日期，不承诺跨批通用矢量语义去重。原生组件 JSON 的完整身份仍可跨页面按 SHA 去重。

第五十六批支持从候选 / 当前工程直接[选择采集原生片段](component-capture.md)后加入同一个队列。此类条目标明“从冻结的原生图件选择采集”，保留原工程与选择指纹、对象和边界处理记录；“入队组件 JSON SHA”对应程序生成的组件字节。有连接受阻 / 文字提示时默认不选，仍需在队列中明确保存。

## 保存、暂停和重试

“将 N 项入库”只提交已选择的有效项，每项沿用原有 `POST /snapshots` 和独立 SQLite 事务。批次不是整个库的原子替换：已保存项不会因后项失败而回滚，原快照不被覆盖。

预览阶段已经冻结完整组件与对应缩略图。提交失败后保留同一份 payload，重试不重新解析 SVG、不改时间 / ID / 来源。若服务器已经保存但回执丢失，重发相同内容会返回原记录。程序核对回执 SHA 后才标成功；与本批已成功内容相同的项复用同一回执，不再请求。

本机请求设有 20 秒时限。写入超时不等于没有写入，界面按结果未知处理，可用冻结内容重试；不会据错误回执标成已保存。

“当前项完成后暂停”保留当前文件 / 页面项的解析或写入结果，然后停止后续项。可继续解析待处理项，或再次提交剩余选中项。收起对话框、切换侧栏不会清空页面级队列；处理可在本页面继续。刷新会清空未提交队列，已经写入的快照仍在本机库。移出 / 清空队列不会删除库内快照。

“导出入库记录”为 `fastfigure.import-report` JSON，记录文件名、原文件 / 组件指纹、提示、状态、错误与成功回执，不包含完整资产、缩略图或本机路径，不能代替库备份。没有增加批量接口或模型自动写库。

## 验证与证据

现有助手 UI 流程增加混合 JSON / SVG、批内重复、无效输入和已提交却丢回执的场景：先保存 SVG，再模拟错误回执，重试取得同一快照，总量仍为两项。原 SVG 检查中补充元数据标题保持断言，没有新建测试文件。

最终 Lint、类型、530 项核心 / 服务检查、构建和四条 1920×1080 UI 流程通过，UI 26.947 秒。UI 仍为五个文件。既有 Vite 导入 / 包体积与 Node SQLite 提示保持。

另外在独立端口、全新浏览器页面和独立库中，使用上一批实际双调用候选的组件 JSON 与原生 SVG：

- 通过受控文件读取等待点观察“完成当前文件后暂停”，留下一个待解析项；切换侧栏后队列仍在，随后继续解析，无效项被隔离。
- 有提示的 SVG 经明确选择后，与原生 JSON 各写入一次；另一个不同原始字节、同规范内容的 JSON 复用回执，没有第三次提交请求。
- 元数据恢复的 80 个节点（包括文字、路径绑定和接口）、九条边、非根容器和快照派生与此前原生采集完全相同；根标题保持源 SVG 元数据，文件 SHA 可核对。
- 当前工程和浏览器工作组件保持，刷新后队列清空、两个已存快照仍可读取。零追加真实模型调用、零浏览器运行时错误。

产物在 `test-results/component-batch-import-ui-v1/`：来源、导入记录、恢复组件、SQLite、实际界面、源码指纹和 `metrics.json`。已查看实际预览。读取等待点用于观察暂停逻辑，不是读取 / 导入性能测量；本例不是独立真实论文批量质量、科学接受或 RSI 结论。

## 相同图形候选

准备预览后核对本机库与本批图形，发现其他相同原生内容时默认不勾选，可并排查看已有快照与来源，或明确保留独立快照。完整快照去重 / 回执不变；索引进度、不可读项和比较边界见[相同原生图形核对](component-content.md)。

第七十三批沿用已有助手 UI 流程，验证同一个 draw.io 文件的原始页、压缩页分别入库，第三个不支持的页面单独失败；每份实际提交的文件 / 页面指纹、文字单元 ID、路径端点绑定与读取回的快照相同，当前工程保持。单图选页 / 子图加入同一队列的实操及离线引擎边界见[矢量导入验收](svg-import.md#验证与依据)。
