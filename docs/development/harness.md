## 端到端流程

1. 检测 CLI 版本；状态只说明能执行，实际运行验证认证、模型与上游服务。
2. 创建或选择当前本地服务中的会话。每个会话持有独立 CLI 适配器和临时目录。
3. 发送当前工程、选中对象、要求与至多 6 项参考组件快照。普通绘图可勾选至多三张参考图并逐张指定用途；重建任务会固定来源和范围，优先从本地原文件生成实际区域裁片。图片作为 Codex localImage 或 Claude base64 内容传递；消息历史只保留裁片尺寸、范围和来源类型等元数据。
4. 普通绘图上下文提供 FigureIR 几何、容量和引用约束，要求返回 `{message, figure, instances, instanceLinks}`；解释时 `figure=null`，修改时提供基础图，并可引用组件实例与连接别名。参考图重建使用独立 Scene 协议，分区修复使用原子 patch，经适配器转换回 FigureIR 后仍走相同审阅链；详见 [结构重建](reconstruction.md)。图片数据由应用保留，不交给模型重写。
5. 流式归一化为 `run.started`、`assistant.delta`、`activity`、`run.completed`、`run.failed`、`run.cancelled`，带 runId、sessionId、sequence 和时间。
6. 最终结果经过 JSON、字段校验、组件确定性展开和完整 FigureIR 校验。只对包裹整个结果的 JSON 代码围栏进行解包，不从任意文本中猜测或拼接 JSON。无效结果保持当前工程。
7. 候选图预览后可应用或丢弃；原有引用图片和被模型省略的已有对象来源由应用保留。应用前再检查工程与运行开始时快照完全一致，应用形成一个历史条目。

该流程不自动评判视觉重建质量。校验能防止悬空连接、越界、非法嵌套等结构错误，不保证模型画出了正确方法，也不保证所有连线路由畅通；受阻线继续使用工作台现有提示。

## 侧栏与组件上下文

参考 FastPPT 的助手布局，左侧“助手”Tab 包含顶部会话切换与内联设置、中部可滚动消息和候选图、底部固定输入框。PC 工作区从左到右依次为导航、素材或助手、画布、对象属性。`WorkspaceSidebar.vue` 统一承载素材面板和助手，固定在工作区第二列；所有左侧 Tab 通过同一导航列表切换并关联此栏位。切换 Tab 仅隐藏助手，不销毁对话、草稿或正在运行的任务；再次打开不会重新加载会话或重置当前审阅详情。关闭助手回到此前的素材 Tab。图库、配色和图标的“用于助手”入口直接切换到此 Tab，图件重建与分区修复也使用相同入口。

画布编辑和快捷键仍可使用；助手输入区保留原生文本操作。应用候选图不会关闭助手；查看旧消息时停止自动滚动，可点击“回到最新消息”。每轮要求、回答、状态与复用记录按顺序显示，历史原始输出和候选图按需加载，切换详情不会删除后续消息。仅维护 PC 布局。

组件来源包括 5 种参数化配方、24 个内置种子和当前浏览器的个人组件。自动模式通过中英文关键词匹配，优先名称和标签，再补充最近个人组件与配方；手动模式可搜索、选择最多 6 项，也可不附带。清单不是 embedding 检索。请求在新建会话前固定工程与组件快照，避免异步期间素材变化；发送前按 UTF-8 大小检查请求预算。

模型只看到组件描述、尺寸、参数定义、节点别名、输入输出别名与来源摘要，个人组件完整结构保留在服务端收到的本轮快照中。返回格式中：

- `instances` 最多 12 项，指定实例 ID、组件键、父容器、位置、标题、节点标签和允许的配方参数。个人组件按保存结构复用，不能重新运行其来源配方覆盖手动修改。
- 实例可用 `scale` 指定比例，或用互斥的 `fit={width,height}` 声明以 x/y 为左上角的放置区域。程序先完成参数 / 图表展开，再统一缩放到区域内，保留左上角并在右 / 下留白；区域须完整位于父容器内容区，计算比例须为 0.1–4，其他碰撞、容量和几何限制保持。复用报告记录请求区域和实际比例。示例及一次真实放置失败见[注意力配方](scaled-attention.md)。
- 所选个人组件的根组合带 `dataChart` 时，实例可附带 `chartOptions` 调用数据图表编译器，调整表现并保留固定输入。重绘覆盖生成图元的手工修改，额外对象保留；不传选项则仍按保存结构复用。运行记录中的 `components[].chart` 由程序产生。契约与实际调用记录见 [图表重绘工具](chart-tool.md)。
- `instanceLinks` 通过原节点、实例内节点别名或输入 / 输出序号连接对象。程序将别名映射到新节点 ID，并保留原生端点引用。
- 展开顺序支持实例父子依赖；程序校验缺失组件、循环依赖、重复 ID、重叠、越界、无效别名与容量。最终受 240 个图元（其中科研节点最多 60）、21 容器、120 条语义连接和 6 层嵌套限制，整轮原子成功或失败。每条原生路径最多 128 个锚点，全图锚点与控制点共 4,096，不占语义 edge 数量。
- `run.completed.components` 来自实际展开结果，记录组件名称、版本、参数与节点数量。来源和派生关系由组件快照带入，可在应用后重新采集入库，不信任模型虚构的组件来源。

这是结构化输出和受控组件编译，尚未注册 MCP 工具，也没有让模型执行组件代码。核心实现见 `src/core/catalogue.ts`、`src/core/assets.ts` 和 `src/core/harness.ts`。

另有独立的数据选型入口：人先导入 CSV / TSV 并填写误差和数据身份，普通运行携带固定 `chartData`，不附参考组件，也不与重建任务混用。模型结合原始表、程序列概况与可选的至多三张实际参考图（样式 / 构图用途）返回图型 / 字段 / 样式建议，程序读取源列生成折线、柱状、散点、同量纲矩阵热图或明确声明为原始观测的箱线图；需要确认或其他形式时只返回分析报告。推荐、备选、标注和未绘制列进入消息与历史，热图另有程序产生的实际数值色标报告，箱线另有固定规则、原始点显示和逐组统计摘要；数值坐标支持 linear / log10 与手动边界，程序产生实际坐标报告并校验正域 / 全部误差端点。原始长表可先返回 prepare 字段映射（行键 / 组键各 1–3 列、单个数值及可选配对误差半宽），由程序预览，用户明确采用为附件后再发起下一轮；原表和选择映射随图表保存，完整规则见 [长表整理](chart-preparation.md)。完整流程见 [数据可视化选型](chart-selection.md) 、[热图](heatmaps.md) 和 [原始样本箱线图](boxplots.md)、[数值坐标](chart-axes.md)。

`materials` 同时提供字体家族、76 个精选图标 ID、当前 / 用户提及的规范配色 ID 与颜色，以及 8 类内部结构的默认标签和推荐尺寸。选中数据图表组件时，还提供其输入配置的配色和 16 组 FigureForge 配色名称、ID 与色值，让模型可按 Publication Soft 等名称选择。模型可使用 `structure={type,repeats,labels}`，并设置 `textStyle`、`descriptionStyle`、`description`、`iconId`、`visual`、`paletteId`。这些字段经 FigureIR 校验，并参与候选差异和组件再次采集；修改同 ID 对象时，省略的现有格式、注释、结构和图标会保留。结构约束与示意边界见 [论文组件结构](component-structures.md)；该结构批次使用契约和浏览器验证，后续图表重绘的实际调用另行记录。

原生图元增加 `path` 和 `port` 类型。路径使用归一化点列及受限的端点绑定，不接受任意 SVG 代码；接口几何由所属自由组合管理。模型省略同类型对象已有的 path / interfaceFor 时保留；组件编译时重映射这些引用。转换后的素材以稳定接口提供清单输入输出，避免把装饰图元误认成模型连接端点。自由组合的结构来源只记录创建时参数，后续手动编辑以保存的图元为准。候选差异报告路径、绑定、接口和外框样式变化。

## 候选图审阅与历史

`src/core/figureDiff.ts` 按节点、容器、连接和参考图 ID 比较，另记录工程名称、画布与主题。报告新增 / 删除 / 修改及字段前后值，包括文本、表示类型、父级、位置、尺寸、端点 / 端口、局部样式和来源。对象键顺序和图对象数组顺序不产生改动；仅节点改名不会误报关联连接已重绑。图片数据只比较是否变化，报告使用替换说明；较长字段展示最多 1200 字符。

侧栏可切换生成前与候选结果，筛选改动、展开字段并定位节点、容器或连接；删除对象自动切到生成前查看。报告反映结构与字段差异，没有自动评判方法正确性或视觉质量，也不把数组顺序当作图层顺序编辑。

服务为每轮维护 `none / pending / applied / discarded` 处理状态。应用仍检查基准工程、仅写一次撤销历史；成功应用后异步保存状态，丢弃也保存状态。重复提交同一决定幂等，冲突决定返回 409。重放历史事件时合并服务当前处理状态，已应用 / 丢弃的图件只读，撤销画布不会自动重置。同步失败保留本页的决定与实际画布，显示重试入口，未同步前暂停该助手的下一操作；刷新页面则以服务记录为准。

未应用的重建候选支持选择分区继续修复。请求通过 `refineFromRunId` 关联保存的父候选，服务校验同会话、待审阅状态、完整快照和重建组范围。模型起点 `baseFigure` 与最终应用的 `canvasBaseline` 分别保存，摘要保留父运行 / 根运行 / 轮次；空补丁保留父候选，失败与取消可回看旧版本。每轮由用户发送，并使用同样的运行时限。流程与验证见 [候选图分区继续修复](candidate-refinement.md)。

在此基础上可启动至多 6 区的服务端核对计划，每区执行一次，使用总预算与单轮预算，状态从 history 恢复。计划运行时锁定该会话的额外运行和候选处理，错误、停止或预算不足不会继续后续区域。它记录内容差异，不自动判断质量或应用；详见 [有总预算的分区核对](repair-plans.md)。

候选分区还可启动独立视觉审阅。两种适配器改为有序 images 数组：普通绘图仍使用一张参考图，审阅按原图、候选渲染发送两张图。审阅新建并释放适配器，不污染原绘图会话；报告只包含问题，不返回 proposal。文字转录只与已知候选文本校验，仍需人工确认原图转录和视觉结论。见 [双图视觉审阅](visual-audit.md)。

视觉审阅的自动上下文使用 `aliases-v1` 几何目录，不附带原生语义 ID、分区标题或来源名称；返回值只接受该次目录的别名，映射回真实 ID 后执行原有文字与只读校验。模型原始输出与规范化报告分开保留。`audit-context.json` 在本轮临时目录保存映射，遵循重型快照清理。用户关注不会被自动改写；这不是完整盲评。见 [目录去语义化与同图对照](visual-audit-context.md)。

问题可单选或多选后合并修复：运行携带 `auditRepair={auditRunId,findingIds}`，服务核对源报告与受审候选 / 分区，并从报告附上完整所选证据。修复摘要保留关联；“复审修复分区”使用这版新候选的实际渲染，再启独立审阅。`visualAudit.recheck` 记录前一报告和修复版本。每步由用户发起，不自动应用；普通 `/runs` 响应现返回 authoritative summary，客户端直接采用。

每会话最多保留 50 条轻量消息，不复制工程、图片与完整事件；当前候选和活动计划起点优先保留，消息记录原始 ordinal，不因其他旧消息清理而重新编号。全局最多保留 20 轮完整运行，保护正在运行及活动计划所需版本；计划结束后优先保留该会话当前候选，普通新运行则保护最新一轮。清理旧运行后保留消息摘要并标明预览不可用，清理对应临时上下文。若浏览器已加载候选图，随后服务清理了其完整快照，仍可在保留的消息记录上提交处理状态。会话与记录仍只存在于本地服务内存，未接入数据库。

| POST | `/api/harness/runs/:id/cancel` | 取消运行 |
| POST | `/api/harness/runs/:id/review` | 记录 applied / discarded，重复同决定幂等 |

普通 JSON 请求大小上限 2 MB，专用计划创建接口为 4 MB（至多 6 张实际裁片，不复制工程）；要求最多 12,000 字符，模型字段最多 100 字符。最多 12 会话、同时 2 执行席位、每会话 1 运行或计划，单轮默认超时 180 秒；请求可明确指定 30–600 秒，界面提供 1 / 3 / 6 / 10 分钟并记录每轮预算。输出与事件数量有界，临时文件使用受限权限。取消与失败只发布一个终态。

接口绑定本地服务并检查 Host / Origin，不提供跨域访问、任意 cwd 或可执行文件输入。CLI 可执行文件只能由服务端环境变量覆盖。Codex 使用 read-only 与 never，关闭 shell / unified exec、插件、hooks、apps 和多代理特性；未支持的主机请求会被拒绝。Claude 关闭内置工具和外部 MCP，使用 safe-mode。当前没有审批队列或通用 MCP 工具执行，模型仅提交建议结构。

SSE 断开不会终止运行，事件缺口或不可读帧会尝试拉取服务快照恢复；同时读取当前处理状态，防止恢复已处理候选图的操作按钮。刷新后恢复会话消息并续接最新运行。服务重启后的会话不存在会明确显示错误，避免无限重连。CLI 自身可能按其设置保留会话记录。删除 FastFigure 会话只清理本应用内存与临时目录，不删除 CLI 自身历史。

重建审阅优先读取本轮实际发送的裁片，而非从可能变化的缓存重新裁取。图片解码与尺寸检查通过后用于叠加，切换消息或卸载组件时释放对象 URL；快照清理、读取失败、图片损坏或尺寸不符会明确回退到工程参考图，并可重试。图片字节独立于 JSON 摘要保存，仍受 20 轮重型快照和请求图片大小的约束，移除会话或重启后清理。

CLI 的细碎文本增量会在 128 字符或 100 毫秒时合并为 SSE 事件，保持文本内容与事件顺序，终态前排空缓冲；活动事件先刷新已有文本。取消和失败同样保留已收到的文本，终态后不再发增量。字符总量、事件数量和运行超时限制保留，避免仅因逐字符流产生过多事件而提前截断较复杂图件。
