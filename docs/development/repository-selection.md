# 助手逐项筛选素材

第四十六批在本机库文字召回之后增加可选的模型筛选。解决“名称命中但不符合本轮要求”的取舍：模型看到完整要求、原生目录与配方声明，再说明哪些候选保留、排除或不确定。筛选判断和生成的图件都需人工审阅。

第五十一批可在该轮“反馈素材适用性”中逐项评价原冻结素材，包含未保留项；同时查看完整要求和当时允许的配方参数。反馈、改判与导出保存在本机，不自动影响筛选或训练，详见[反馈样本](retrieval-feedback.md)。

## 使用

左侧助手 → 参考组件 → 按要求自动检索，开启本机库检索后，可勾选“先由助手筛选素材”。偏好会保存，默认关闭；开启会增加一次模型调用，与本轮绘图或规划共用所选时限，没有独立追加预算。

普通直接绘图与首次规划可用。数据选型、重建、分区修复、手动指定素材和已采用方案保持各自边界。采用方案时恢复规划最终选中的完整快照，不重复筛选或检索。

初次重建另有[看图寻找重绘素材](component-image-search.md)入口：两阶段都接收同一实际裁片，第二阶段另附完整候选池的实际图谱。原生目录在看图分析之后形成并冻结，浏览器渲染与传输校验完成才调用筛选；明确采用后才交给重绘。

每轮“本机素材召回 → 助手逐项筛选”显示保留 / 排除 / 不确定、理由、引用的要求原文及冻结内容指纹。已存项可查看原始组件。点击“核对筛选原始记录”可读取完整提示与原响应，程序重新核对 SHA 后展示；服务重启或运行清理后原记录不可用，摘要仍按现有会话保留规则处理。

普通绘图 / 规划的筛选阶段仅看文字与原生目录，不接收参考图。参考图片继续在后续绘图 / 规划阶段处理，不据此声称视觉理解或视觉相似度筛选。

## 候选与契约

1. `metadata-keywords-v2` 仍负责初筛：库中至多 24 项文字候选，读取完整资产、重验 SHA、追加便携来源，与发送前工作组件 / 内置素材合并。按现有权重排序、精确去重，最终固定至多 24 项候选；截断会报告。模型不能扩展到未入池的全库。
2. 程序记录每个候选的 key、修订、完整候选资产 SHA 和可选的原始库存 SHA。两种 SHA 不混同：库存 SHA 指原文件，候选 SHA 包含本轮名称空间与快照派生记录。完整结构在模型工作前已冻结，不靠生成后再读取当前库。
3. 独立的新模型会话收到名称 / 标签 / 说明、原生节点与边数量、结构类型、部分标签 / 接口 / 来源及 `declaredRecipe`。目录有预算，不能把未展示内容认作不存在；配方字段是来源声明，手工编辑后可能过时，不能作为科学正确性证明。
4. 模型逐项返回 `include / exclude / uncertain`，每项恰好一次、简短理由与一至三段逐字要求引文。最多保留六项，允许零项。`uncertain` 不附带，后续仍可自行绘制。
5. 程序校验已知 / 唯一 key、逐项完整、六项上限、引文确实属于本轮原文、字段与响应预算。原文校验只证明引文真实，**不证明理由或相关性正确**。模型不能通过这个响应修改资产、注入新素材或自行写库。
6. 只有保留项进入绘图 / 规划上下文与组件编译器；未选中 key 即使出现在报告中也不能实例化。失败、无效响应或超时直接结束本轮，不自动重试或退回词匹配清单。候选图件仍需显式应用。

目录摘要最多 24 个原生标签、12 个结构声明、16 个命名接口和三条来源；标签另报遗漏数。完整结构用于最终编译与源组件详情。摘要预算、文字初筛的遗漏和噪声仍是边界，不能把本功能视为完整结构验证。

请求字段 `libraryReview?:boolean`，必须同时开启 `librarySearch`。缺省保持一次绘图调用。报告位于 `summary.repositoryRecall.selection`，记录候选、状态、理由、CLI / 显式模型参数、耗时、原文指纹；没有报告的具体模型身份不猜测。`repository.updated` 事件同步筛选结果，重连恢复与历史使用同一份程序记录。

只读原始记录接口为 `GET /api/harness/runs/:id/selection-evidence`，返回本轮提示、可选原响应及 SHA，沿用本机 Host / Origin 限制，不暴露服务器目录。运行中的 full snapshots 在筛选结束或失败后释放，规划保留最终六项；原始提示 / 响应随运行记录清理。

## 验证

在原有服务检查文件中增加一个完整场景，遍历 Codex / Claude：能从超过六项的候选中选择原先未入前六的素材，筛选期间发布新版本不改变已冻结结构；拒绝未知引用、假引文、遗漏项与无效 JSON；空选 / 不确定不补参考；立即取消不遗留“筛选中”；方案采用不再次检索或筛选。

现有助手 UI 流程增加开启设置、逐项结果、原响应指纹核对与源组件查看。没有新增 UI 文件或流程，仍为五个文件、四条 1920×1080 流程。Lint、类型、530 项核心 / 服务检查、构建及四流程通过，UI 23.345 秒。既有 Vite 导入 / 包体积和 Node SQLite 提示保持。

## 一次真实筛选与绘图

在独立目录使用已有 16 份自制素材与三项发送前内置候选；文字初筛后固定 12 项。要求为单头无掩码注意力与输出张量叠片，明确禁止因果掩码、解码器及重复部件，给出 1000×620 画布与 fit 区域。

真实 Codex CLI 0.165.0，两次调用共 114.911 秒，筛选阶段 43.404 秒。具体模型身份未报告。模型选中已存 `Unmasked attention` 与中文张量叠片，排除因果项、双语解码器、编码器和重复用途素材；所有引用均属于完整要求原文。

第二次调用直接得到待审候选，原始响应没有修补：80 个原生图元，注意力八条内部边加一条命名输出连接，共九条边；两个已存组件的参数、标签（仅明确清空重复注意力标题）、比例、路径绑定、内部拓扑、接口及快照来源已核对。相对几何最大数值误差约 `1.14e-13`，九条路由均 clear，20 个原生文字字段无截断报告。重新编译同一原响应与服务候选完全相同。
