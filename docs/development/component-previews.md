# 重建时的实际组件图谱

第三十九批补上库素材辅助重建的视觉输入。上一批真实模型仅凭清单选择 tensor，并明确不知道它的逐层外观；实际候选与原图五层橙色透视片差别很大。本批让模型和人回看同一份实际组件图谱。

## 使用

在左侧助手开启“库素材辅助重建”，选择组件并发送。程序先冻结所选快照，随后准备原图裁片与组件图谱。准备期间画布变化会阻止提交；库内素材变化不会替换已冻结的输入。渲染失败或请求超过容量时明确报错，尚未启动模型。

第 1 张输入是需要重建的原图裁片，第 2 张是组件默认外观图谱，格子编号和 key 与目录逐一对应。单格 800×480，最多六格、两列三行；同一批至多增加一张图像。浏览器使用与现有图元相同的 SVG 场景，并按实际加载的字体处理文字，再生成白底位图。配方变参、修改标签或缩放后的结果没有在图谱中预演，提示明确要求另行核对。

运行历史显示目录和“查看本轮组件图谱”，读取的是本轮保存字节，不是重新渲染当前库。查看时核对 SHA-256、解码和像素尺寸，可切换原始像素并滚动。清理运行后显示不可用，保留的轻量目录不含图片 data URL。

## 结构与输入核对

除既有可调用素材清单，重建提示增加节点位置 / 尺寸、结构参数、命名接口、容器、完整内部语义边和默认配置。每项最多详细描述 80 个节点，明确报告总数、已描述数和省略数；自由路径只提供锚点数量 / 箭头 / 闭合概况，不冒充完整控制点目录。实际图谱仍显示完整保存外观。

图谱绑定有序的完整素材快照规范 JSON，并记录快照 SHA、图片字节 SHA、像素尺寸、格子与所用字体请求。服务在启动模型前核对素材内容与顺序、目录、实际图片头和字节指纹。CLI 依次收到源裁片及该图谱；不会把 base64 嵌入文本提示或历史消息。

服务核对证明收到的字节与声明的快照 / 指纹一致，不是独立的渲染正确性证明，也不证明模型逐项理解了图片。实际渲染由本机浏览器完成，默认协议测试使用明确标记的夹具。

被复用的容器在 `reconstructionReuse.cataloguePreview` 保存图谱 SHA、素材快照 SHA 和格子号，随捕获、缩放、插入及原生 SVG 元数据保留。完整图谱图片只在本地服务运行记录中保存，遵守原有运行清理规则；单张 data URL 不超过 600,000 字符，整次提交继续不超过 2 MB。

## 一次真实开发样例

从已有原生生成图片裁取 Embeddings 输出区域，附带 tensor、volume、encoder、attention、MLP、fusion 六项的实际默认图谱，真实 Codex CLI 0.165.0 调用一次。运行 `d0a2311c-56f2-4e0c-9655-5a8ee2e21f06`，134.232 秒完成，没有重试或重新生图。

实际图谱为 1600×1440，106,598 字节 WebP，SHA-256 为 `055fb3e96cf0930f7274acffa7af665f37f56ad6c337bf6fceec4200d97be202`。已查看图谱、实际源裁片与候选，并核对六项完整素材快照、编译源码和图谱字节。

模型说明 tensor 虽语义接近，但实际为蓝灰圆角卡片叠层、小网格图标、内部文字和外围面板；volume 是长方体，其余四项为计算结构，均不匹配源图橙色斜向片层与整面网格，因此选择 `reuse=[]`。返回 17 个独立描摹节点，其中 15 条路径、2 个定位文字，保留可见五片叠层、标题和图例，未补入被裁断的输入箭头。原始内容规格与所有描摹节点的 AI 来源保持，候选仍待审，未应用到用户画布。

该例中，模型对库外观作出了具体而与实际图谱一致的说明；同时说明渐变、字形、网格与曲线仍是矢量近似。文字检查没有检查这两个定位文字，零项报告不代表整图文字通过。本轮裁片、候选清单及要求均不同于上一批整图实验，不能当作受控前后对照或总体质量提升结论。

输入、实际图谱 / 裁片、六份完整组件、原始响应、候选 / SVG / PNG、捕获组件、运行记录、源码指纹与核对结果保存在 `test-results/reconstruction-library-atlas-live-codex-v1/`。

## 当前边界

图谱展示的是已经选中的至多六项，不是全库视觉检索；当前检索仍按名称、标签和说明进行。原生结构与图片仅近似匹配，科学含义、颜色、连线和字形需审阅，不做自动质量接受。自由路径与原生命名接口的语义绑定、图片嵌入检索、素材同步和 RSI 仍待开发。
