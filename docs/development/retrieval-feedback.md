# 素材适用性反馈与样本积累

第五十一批将本轮素材选择的反馈接入本机持久存储。入口在左侧助手的“本机素材召回 → 反馈素材适用性”；历史入口在“组件 → 本机素材库 → 素材反馈记录”。

## 使用

本轮结束后，选择一份候选，查看完整要求、原生预览、是否附带，以及助手原有取舍理由和要求引文。选择“适合 / 不适合 / 不确定”，可补充至多 1000 字说明，再明确保存。初始没有默认判断。

原生配方预览是当时的默认形态；界面另列当时允许的参数选项，避免把默认外观当作全部能力。保存的手工快照按冻结图元复用，配方来源不代表可重新生成。评价针对参考素材能否用于本轮要求，不是最终图的质量评定。

保存后可以改判，旧记录仍保留。保存失败会冻结同一请求，重试不重复追加；若其他页面已先改判，服务器拒绝用旧记录覆盖，重新读取后再决定。没有变化时不追加记录。

反馈记录页按素材名 / 完整要求的文字片段检索，并按最新判断筛选。可以打开完整样本、继续改判、导出单个 JSON，或导出当前筛选的全部样本为 JSONL；导出不限于当前分页。服务重启、原运行清理或素材归档后，已经保存的样本仍可查看、改判和导出。

这些反馈只用于积累样本，不改变当前图件、本机召回排序或素材归档状态，也不自动训练或晋升模型。通过界面或 API 提交的判断不等于已核实的独立人工标注。

## 冻结与身份

服务在逐项筛选或绘图之前，把候选的规范原生组件写入本轮临时目录，记录指纹和可调用参数。逐项筛选会保留整个筛选池，包括排除项；采用规划时复制原池到新轮目录，不依赖原轮目录继续存活。反馈读取这些冻结内容，不读取后来修改的工作组件，也不按当前配方重新补参数。

临时素材仍遵循最多 20 轮重型快照的保留规则，随运行清理。首次保存需要冻结内容仍在；保存之后，所评素材与上下文独立存入数据库，不依赖会话或临时文件。

服务器根据运行和已知 key 构造上下文，客户端只提交判断、说明、请求 UUID 和上一条记录 ID。拒绝客户端伪造图元、要求或来源。上下文保留完整召回记录、用户要求、提供方 / 已报告模型名、原生图元、来源和参数能力；规划沿用关系仍在报告中。

来自[看图找素材](component-image-search.md)的记录还包含实际裁片字节、图片 SHA、看图观察与取舍；弹窗在原生预览下显示当时的裁片。采用后重绘的反馈继续沿用该证据。它在明确保存后独立于原会话与运行临时文件，但不包含看图 / 筛选提示与响应的全部正文。素材与裁片合计受同一 2.4 MB 边界约束，超限拒绝，不静默压缩或删减。

`assetSha256` 对应实际冻结的组件，可能包含工作身份和快照派生记录，与库中原组件 SHA 不一定相同。原库指纹仍在匹配记录和来源链中。`caseId` 是完整规范上下文的 SHA，包含运行 ID 与候选 key；每次判断另有 UUID、时间、前条 ID 与内容 SHA。

单个样本只保存所评素材的完整原生快照。报告中其他候选的元数据 / 指纹并不代替其完整图元；未评价项不是负例。这不是候选全集、完整模型运行转储、独立盲测或完整召回率标注。没有参数目录的旧样本不按当前配方补填。

## 本机存储与导出

沿用 `FASTFIGURE_LIBRARY_DIR` 与 `components.sqlite`，新增独立的 `retrieval_contexts` / `retrieval_feedback` 表，不将反馈当作已发布素材。一个运行 / 候选 key 只能绑定一份不可变上下文；判断为追加链，前条 ID 提供并发检查。同一请求的成功回执在原运行清理后仍可重取。

容量为最多 1000 个上下文、5000 次判断、300,000,000 字节的上下文 / 请求 / 判断 JSON；每个上下文最多 2.4 MB，每个样本最多 100 次判断。索引与 SQLite 日志另占空间；组件库状态中的数量 / 正文大小仍只统计素材快照。超限明确拒绝，不截断证据。备份整个目录会包含反馈表；当前没有反馈删除或自动清理。

单个 JSON 使用 `fastfigure.retrieval-feedback` 格式，含上下文和全部改判记录。JSONL 首行是 `fastfigure.feedback-export-start`，末行是 `fastfigure.feedback-export-end`，两行给出样本数与序号边界；中间每行一个完整样本。导出先冻结匹配样本与判断序号，过程中追加的改判不会混入本次文件。缺少结束行或数量不符不能当作完整导出。

浏览器和服务核对上下文、原生组件、记录 SHA 与改判链。这是内容一致性检查，不证明提交者身份、判断正确或独立，也不能防止可重写整个数据库的人重新计算指纹。

## 接口

沿用本机 Host、同源 Origin 和请求大小约束。模型适配器没有这些写入工具。

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| GET | `/api/harness/runs/:id/retrieval-context?key=...` | 读取服务构造的冻结样本；已保存项可脱离原运行读取 |
| POST | `/api/harness/runs/:id/retrieval-feedback` | `{id,componentKey,rating,note,previousId}`；新记录 201，重复回执 200 |
| GET | `/api/component-library/feedback?q=&rating=all&offset=0&limit=12` | 每个样本的最新判断，每页最多 24 项；可按 runId 筛选 |
| GET | `/api/component-library/feedback/:caseId` | 完整上下文与改判链 |
| GET | `/api/component-library/feedback/export?q=&rating=all` | 当前筛选的 JSONL 流式导出 |

## 验证范围

在已有存储文件中增加一项数据一致性场景，核对请求去重、改判、并发冲突、导出序号、重启和损坏拒绝。既有双 CLI 场景核对冻结文件篡改、运行中素材改变 / 归档、清理原会话后继续反馈，以及采用规划后仍可查看被排除配方的原池和参数。共 513 项核心 / 服务检查、40 个文件通过。

现有助手流程覆盖丢回执重试、说明冻结、改判、单样本核对、本机历史和 JSONL 完整导出；没有新增浏览器测试文件，仍为五个文件、四条 1920×1080 流程。Lint、类型与构建通过，最新四流程 27.946 秒。

独立页面用上一轮的原始模型响应作一次离线协议回放，预览 134 图元 / 九边配方并记录三次开发判断。服务重启、临时运行文件删除后，样本仍可查看并追加第三次判断，JSONL 与原上下文 / 图元 SHA 保持，工程和素材库未被改写。证据在 `test-results/retrieval-feedback-ui-v1/`。

另一次独立回放核对原生配方能力：只在该进程内暂时增加一个当前目录选项，已冻结上下文仍保留原来的 2 / 3 / 4 格范围；实际界面与导出均核对。补充证据在 `test-results/retrieval-feedback-capabilities-ui-v1/`。两次均为既有响应回放，零真实模型调用；标签由自动化操作提交，明确是开发样例，不是独立人工标注。
