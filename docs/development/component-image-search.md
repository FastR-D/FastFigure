# 看图寻找重绘素材

参考图初次重建支持先看图找素材，再由人采用并发送原生重绘。它把已有的图片输入、本机文字召回、逐项模型筛选和组件图谱串起来；当前没有图片嵌入或像素相似度排名。

## 操作

1. 在“参考图”导入图片，准备整图或框选区域重建。
2. 在左侧助手填写要求，点击“看图找重绘素材”。这轮通常包含两次模型调用，共用所选的 1 / 3 / 6 / 10 分钟时限；不会生成候选图或改变画布。
3. 展开“看图素材检索”，核对实际裁片、可见线索、不确定项和逐份素材取舍。可读取看图与筛选原响应并核对指纹，也可评价候选的适用性。
4. 点击“采用素材并准备重绘”。助手保留当时的裁片与所选原生快照，显示所采用的素材；发送时才生成实际组件图谱，供重绘模型比较。
5. 再次发送重绘要求。模型可以在选定素材基础上组合，也可以描摹其他区域；返回可审阅的原生候选，最终仍需手动应用。

没有选中素材时，可以“准备原图描摹”，或手动选库组件。失败后可重新准备检索，不自动增加模型调用。采用后改变画布或参考图会阻止旧结果生成，需要重新找素材或还原画布。清除采用结果后回到手动选择。

## 两阶段输入与冻结

第一阶段实际接收重建范围的裁片，返回简短描述、至多十二条有位置依据的线索，以及待核对事项。只有 `visible` 词附加到原始要求中参与文字粗排；`uncertain` 项保留展示，不自动加入查询。是否可见仍是模型判断，不是程序证明。

程序检索内置组件与本机当前快照，粗排池最多二十四项。浏览器将完整候选池按每页六项生成至多四页实际图谱。第二阶段在独立模型会话中接收同一份实际裁片、依次排列的所有图谱，以及冻结的原生目录；逐项返回保留 / 排除 / 不确定，至多保留六项。原因需要引用用户要求的真实片段。图片一始终为原裁片，图片二至五按页展示候选的默认 / 保存外观；同页格号与原生目录 key 对应。图谱不展示参数变化后的所有效果，原生目录也有标签和结构摘要的展示上限。

候选池在**看图分析返回之后、浏览器渲染与逐项筛选之前**形成并冻结。因此第一阶段运行期间的库修改可能影响入池；筛选期间及采用后的库修改或归档不会替换已冻结内容。数据图不能借用其他素材的观测值参与重建，目前在池形成后排除，所以可能占用粗排预算；这不是完整的库级召回。

原始用户要求最多 12000 字，增加可见词后的内部查询预算为 14000 字，报告同时保存原文与实际查询，不静默截断原文。文字分词、别名和候选预算仍有局限，详见[本机素材召回](repository-recall.md)。

## 实际候选图谱的等待与恢复

冻结后服务发布待渲染请求，左侧助手自动读取完整候选并在浏览器生成实际图谱；不预先缩减为最终六项。请求与提交关联运行、会话、请求 UUID 和候选池指纹；服务校验每页素材快照、顺序、像素尺寸及字节 SHA，全部成功后才调用筛选模型。

浏览器需要保持连接。切换左侧 Tab 不停止渲染；页面刷新后可读取同一待处理请求并继续，仍受原运行时限约束，不重新分析图片。重复提交同一图谱幂等；上传成功但回执丢失时，页面读取已接收的指纹，避免重新生成或误判失败。不同图谱冲突时拒绝。

取消、超时、字体 / 渲染失败或校验错误会结束该轮；不会静默跳过页面或改成只看文字。空候选池无需渲染或筛选调用。第二阶段最多接收原图加四页图谱，仍使用同一运行预算。

本轮详情可以按页回看实际发送图像、目录与指纹，支持原始像素查看。图片来自受信任的本机编辑器；元数据和 SHA 能证明冻结与传输一致，不能单凭 SHA 证明渲染器或模型判断正确。运行清理后不以新渲染替换历史图片。反馈仍保存所评原生素材、原裁片和图谱目录 / 指纹，没有持久化整个候选池的图谱字节。

## 采用与证据

`component-search` 返回冻结裁片、基准工程、重建任务、选定原生组件及指纹。浏览器核对图片字节和素材目录指纹；服务核对同会话、基准工程、范围、实际裁片和配方能力。重绘请求只提交来源运行 ID，由服务恢复冻结清单，不信任浏览器替换的素材。

重绘发送的图片一为检索时的实际裁片，图片二为浏览器从所选快照生成的实际图谱；普通重建的几何、容量、匹配区域、差异说明和待审阅约束继续生效。原生组保留素材来源、参考图区域和图谱指纹，见[素材辅助重建](reconstruction-library.md)。

看图与筛选的提示、响应、SHA、CLI 已报告版本和阶段耗时可以在本轮查看。模型字段为空时表示使用 CLI 默认配置，不能推断具体模型身份。耗时和示例结果不作为质量或性能承诺。

本轮重型快照仍在服务内存与临时文件中，重启或清理后不能继续采用。明确保存的素材反馈会另外持久保存当时的实际裁片、观察、取舍、原生组件和指纹，原会话清理后仍能对照；原始提示 / 响应正文没有因此全部持久化。上下文沿用 2.4 MB 边界，素材与裁片合计超过时拒绝保存，不缩减图片或图元。见[素材反馈](retrieval-feedback.md)。

## 验证范围

常规检查复用已有核心 / 服务文件和重建 UI 流程，没有新增逐按钮脚本。覆盖两种 CLI 的实际图片协议、可见与不确定词分流、12000 字原文、坏分析 / 空选择、冻结后修改与归档、跨会话或换图拒绝、采用不重新检索、真实图谱，以及裁片随反馈保存后的校验与服务重启读取。

这些协议检查不能证明模型看图正确、最优匹配或科学质量。独立论文相关性标注、素材渲染后的受控比较、嵌入检索、样本工厂和 RSI 仍需继续开发。

## 第五十四批历史闭环

此历史样例的筛选阶段只附原裁片与原生目录，尚未附候选图谱。使用自制 1000×620 叠片参考图、同构原生快照，以及名称相似但只有一个矩形的受控干扰项。源图来自已有原生组件，因此这是可操作性开发样例，不是独立相关性或论文质量评测。

Codex CLI 0.165.0 的三次真实调用分别为看图 28.878 秒、逐项筛选 54.653 秒、采用后重绘 40.560 秒；具体模型身份未报告，没有模型重试。看图观察到错位叠片和前片网格，把侧线接口语义标为不确定。十六项候选中保留两项片层结构，明确排除名称相似的单矩形，另两项不确定，不自动补入。

通过实际界面采用后，重绘收到同一裁片与两项素材的 1600×480 实际图谱，生成十八个原生图元、两个容器，并复用手工快照。内部片层、网格、文字与接口保持；最终位置、留白、线宽和透明度仍需核对，未声称像素复刻。候选没有应用，源素材与原工程保持。

已查看看图记录、冻结裁片、反馈表单、实际图谱及候选 PNG。反馈明确保存为“自动化开发记录 / 不确定”，在原会话清理和素材库重新打开后，实际裁片与完整上下文保持一致；它不是独立人工标签。三次实际输入的图片字节、提示 / 响应、原生候选 / SVG / PNG、二十九份运行期源码快照与核对记录在 `test-results/component-image-search-live-codex-v2/`。

最初临时验证入口的 API 挂载错误保留在 `...-v1/`，该次零模型调用。之后补充入口就绪禁用，并将反馈明确标为“检索时完整要求”，避免采用后把旧要求误读为新重绘要求；这些界面修改不改变模型输入协议，没有为这一控件改动再次调用真实模型。


## 第五十五批实际候选图谱样例

用自制叠片图及两份保存素材验证：Candidate A 保持独立片层，Candidate B 将片层移到完全重叠的位置。两份素材的配方来源、原生节点数、类型、标签、说明摘要相同，实际外观不同；它们的差异没有通过额外文字答案告诉筛选模型。

两次真实 Codex CLI 0.165.0 调用分别为 19.041 秒与 53.403 秒，另有 0.532 秒图谱渲染 / 传输往返。第一阶段只接收原裁片，第二阶段接收同一裁片加两页覆盖十一项候选的实际图谱。最终保留三项参考；其中保留 A，排除 B，理由明确指出 B 只显示单张网格片、侧线与主体分离，不能只凭配方来源和五层标签认定外观正确。

已逐页查看实际输入及 UI，核对三张筛选图片的顺序和字节指纹、完整目录覆盖、源码快照与反馈保存。原图和源素材保持，未应用、未重绘或自动晋升素材。完整记录在 `test-results/component-selection-atlas-live-codex-v1/`。这是一个受控自制样例，没有相同输入的文字筛选对照或独立论文标签，不能据此计算准确率或声称因果质量提升。

之后只调整了默认 / 保存快照的标题说明及入口说明；另用已保存原生素材进行零模型渲染核对，没有重新做真实模型实验。`test-results/component-selection-atlas-resume-ui-v1/` 只回放原响应，验证等待图谱时刷新可恢复同一个运行，零新增模型调用，不作为新的模型判断。

常规核心 / 服务检查为 522 项、40 个文件；四条 1920×1080 流程通过，仍为五个 UI 文件。UI 首次定位范围错误和随后变量作用域错误均保留，修正后全流程 29.300 秒。最后的图谱标题由离线实际渲染核对，入口说明由 Lint、类型与构建检查；没有新增逐功能验收文件。
