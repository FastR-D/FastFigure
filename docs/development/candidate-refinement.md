# 候选图分区继续修复

2026-10-29。在参考图重建候选上直接选择分区继续修复，保留之前的候选和最终应用前的画布。本文记录用户逐轮驱动的单区版本迭代；每轮均需发送，不自动评分接受或应用。后续增加的有界批量模式见 [有总预算的分区核对](repair-plans.md)，两者均不属于 RSI。

## 操作

1. 在左侧助手中生成参考图重建或分区修复候选。
2. 展开候选下的“继续修复候选”，选择语义分区或细节区域，选择文字、缺漏图元、连线箭头、轮廓颜色或综合核对，可补充具体问题。
3. 点击“准备候选修复”。底部显示以候选为起点的提示，可以编辑要求、取消准备，或按“发送要求”启动。每轮仍使用 1 / 3 / 6 / 10 分钟的运行时限，可随时停止。
4. 新结果先叠加核对。可切换“本轮修复改动”和“累计画布改动”；前者比较上一版候选，后者比较最初画布。
5. “查看上一版候选”回到父版本；该版本仍待审阅时，可以从它再发起分支，或选择它应用。修复失败、取消或丢弃不修改父候选。
6. 最终点击“应用候选图”，整条分支只写入一次画布历史，单步撤销回到最初画布。查看与发送候选期间的画布编辑仍会触发过期保护。

如果修复返回空补丁，结果保留上一版候选并记录新轮次，便于明确结束该轮核对；不会因为局部无改动而丢失尚未应用的完整重建。历史回看受现有 20 轮完整快照、50 轮轻量消息和服务内存生命周期限制，服务重启后不承诺恢复。被清理的父版本按钮会禁用；子版本保有自己的起点、最终候选和画布基准。

## 快照与范围

`POST /api/harness/runs` 增加可选 `refineFromRunId`，仅允许 `task.kind=repair`。服务启动 CLI 前检查：

- 父运行属于同一会话，已完成，有尚未应用或丢弃的重建候选。
- 本次 `figure` 经模式解析和 JSON 传输格式规范化后与保存的父候选逐字段相同，保留图元数组顺序检查；仅忽略传输中无法保留的 `undefined` 可选字段和对象键顺序。客户端不能把其他工程冒充为某个候选。
- 修复目标必须是父轮创建或修复的重建分组。有效分区、原图来源、实际裁片尺寸和修复目录继续按现有契约核对。

每轮保存两份不同用途的快照：`baseFigure` 是模型本轮实际修改的上一版候选；`canvasBaseline` 是这条分支最初的画布。父候选与两份基准均由程序维护，模型只收到当前分区目录和原图裁片。保护手工对象、其他分区、稳定 ID 和版本补丁的规则继续有效。

消息摘要增加 `refinement={parentRunId,rootRunId,round}`，完整运行接口同时返回 `canvasBaseline`。浏览器恢复历史和最终应用都使用画布基准，避免把“画布尚未应用上一版候选”错误判成过期，也避免覆盖用户在重建期间做的修改。只修改模型起点而复用旧的应用判断会产生这两个问题。

这是同一会话中的显式候选分支，暂不支持跨会话转移候选。用户返回此前版本时不会自动删除后续消息，也不会自动回退画布。父候选已应用或丢弃后不能再作为新请求的起点；已应用图可继续使用属性栏的常规分区修复。

## 验证

- Codex / Claude 测试 CLI：初建 → 尚未应用的局部修复 → 空补丁保留 → 从早期候选开分支；核对初始基准不变、无关对象不变、版本链和 HTTP 快照。
- 服务拒绝跨会话、伪造快照、错误重建组、无效分区及已处理父候选，在启动 CLI 前返回错误。
- 修复失败或取消后，父候选逐字段保留，可以重新发起。
- 客户端恢复历史后区分上一版候选与最初画布；并发编辑阻止应用，撤销编辑后可一次应用全部分支并单步撤销。
- 初次打开助手时，恢复旧会话保留刚从参考图显式准备的新任务，避免异步会话加载覆盖用户的新要求。
- PC 浏览器覆盖准备与发送、具体问题、过期发送拦截、累计对照、空补丁、刷新恢复、失败 / 取消回看、应用 / 撤销 / 重做和 1280 / 1440 / 1920 左侧栏。

本批没有新增收费模型调用，协议检查使用 CLI 夹具，浏览器使用独立上下文与自制参考图。它们证明迭代链及状态处理，不能证明真实论文的视觉质量有所提升。独立诊断评分器仍不参与自动选择或接受候选；下一步需要更多标注和真实模型对照，再设计有总预算、停止条件和回滚的自动调度。

最终 `pnpm test` 为 20 个测试文件、257 项通过；`pnpm lint`、包含类型检查的 `pnpm build` 和完整 `pnpm test:ui` 均通过。新增浏览器过程输出在 `test-results/candidate-repair-checkpoints.json`，PC 截图为 `candidate-repair-1280.png`、`candidate-repair-1440.png`、`candidate-repair-1920.png`。这些是忽略提交的本机验收产物。
