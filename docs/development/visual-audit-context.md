# 审阅目录去语义化与同图对照

2026-10-29，第廿批。目标是减少审阅模型从对象名称猜测内容的机会，同时保留问题定位、候选文本核对和分区修复能力。没有增加自动接受、自动训练或 RSI。

## 自动上下文

`createVisualAuditContext` 固定本次分区快照，按几何位置、类型和只读状态排序，以 `v0001` 等临时别名组成目录。几何相同的重命名快照会得到逐字节相同的审阅提示。模型只收到类型、归一化位置和只读标记，不收到原生 ID、节点名称、候选文本、分区标题、工程标题或来源名称。

别名只在该目录里有意义，不承诺不同分区或不同版本中的同一别名对应同一图元。模型必须引用目录里的别名；原生 ID 和未知别名均拒绝，不提供旧协议回退。服务先把别名转换回固定目录的原生对象 ID，再核对文字转录、可编辑范围与只读限制；规范化问题报告和合并修复继续使用真实对象引用。原生 ID 恰好长得像别名时，也按当前别名表解析，不猜测其含义。

Run 摘要的 `visualAudit.contextVersion` 为 `aliases-v1`。完整提示存入 `context.txt`，目录与别名表存入 `audit-context.json`，规范化报告存入 `response.json`；原始模型输出通过既有事件流保存。文件遵循同轮重型快照和会话清理，没有新增永久存储。

这个改动只处理程序自动附带的语义线索。实际图片、对象类型和几何仍有意义；用户输入的关注、旧问题标题和模型先验也可能提示答案。不会改写用户要求或隐藏图中文字。因此不能称为隐私匿名化、全面盲测或独立外部质量基准。

## 可复算的开发样例

固定数据位于 `benchmarks/visual-audit-context-v1/`：原图裁片、实际发送的候选渲染、可编辑工程、SHA-256 清单和独立存放的已知缺陷。源图为自制 800×400 简单图，实际裁片为 328×268；候选源自较早模型生成的可编辑图，随后确定性改成 Ecnoder 并删除内部蓝色曲线。

它是已有实验使用过、开发者可见的单个开发样例，不是留出样例或真实论文。已知缺陷只记录两项受控修改，不是对字体、几何或其他样式差异的穷尽标注；没有额外声明公开再分发许可。标签文件不进入模型提示。

离线校验全部文件与工程指纹，生成两组完整提示，不调用模型：

```bash
node scripts/evaluate-visual-audit-context.mjs --output test-results/audit-context-new
```

也可使用 `pnpm benchmark:audit-context --output test-results/audit-context-new`。

显式做两次真实调用，各有独立适配器、工作目录与时限，不自动修复或重试：

```bash
node scripts/evaluate-visual-audit-context.mjs \
  --output test-results/audit-context-live-new --live --kind codex --timeout 180
```

两组使用相同图片字节、几何目录、任务说明和关注文字。别名组只附带几何别名；语义对照组换回原生 ID 并附上分区名称。默认顺序从候选图片指纹导出，可用 `--order semantic-first` 或 `--order aliases-first` 指定；`--model` 可指定 CLI 模型，否则身份可能不报告。默认一次每组，不形成统计意义上的随机实验。

输出目录必须是新的，避免覆盖未知结果。记录包含输入指纹、提示、执行前保存的源码快照、版本、时长、活动、原始响应和规范化报告。语义对照组的原生 ID 到别名转换仅在实验脚本中存在，生产 API 不接受这个旧格式。失败也保留，不为获得绿色结果自动重跑。

## 一次真实同图对照

2026-10-29，Codex CLI 0.165.0，默认模型身份未报告，先别名后语义对照，单轮预算各 180 秒：

| 条件 | 耗时 | 开发者核对报告 |
| --- | ---: | --- |
| 几何别名目录 | 33.068 秒 | 指出波形缺失，逐字转录 Encoder / Ecnoder，引用正确标签 |
| 语义名称目录 | 30.246 秒 | 同样指出波形缺失和字母顺序不同，引用正确标签 |

两组图片 SHA-256 完全相同：原图 `5a7e1a582f33870469c1cfa38aeac3072b3e66c0dfde9d858acab9a6b9e2e751`；候选 `1df502dd46657c69051987e4ad23cc85ed43837719018643b0b67076d7769197`。两份规范化报告均保留两项问题，文字转录与本地候选一致；实验没有发送修复或应用工程。

原始记录位于 `test-results/visual-audit-context-live-codex-v1/`。当时从保存的真实审阅目录读取输入；随后将相同输入打包到开发数据中，并用 `dataset-link.json` 逐字节确认两张图片、工程文件及两组完整提示一致。原运行记录和执行源码快照没有被改写成后来的打包版本。

这个结果说明该样例不依赖语义 ID 也能定位两项受控问题，不能据此宣称准确率提高、速度更快或适用于复杂论文。样本量、模型随机性、调用顺序、已有开发使用和非穷尽标签均限制结论。真实论文人工标注、更多 OCR / 字体 / 遮挡 / 图语义样例和统计对照仍待开展。

## 验证

新增语义 ID / 标题 / 来源重命名后的提示不变性、未知 / 原生 ID 拒绝、别名外观的原生 ID 冲突、正确回映射及固定数据指纹检查。两种 CLI 协议测试验证有序双图和模型目录，原始别名响应仍可定位、转录核对和合并修复。PC 流程继续覆盖 1280 / 1440 / 1920 的报告、过期保护、合并修复、复审、刷新和一次撤销。

累计 290 项单元 / 集成检查，新增 4 项；类型、Lint、构建和完整 PC 浏览器回归通过。另一次定向浏览器回归检查原始 SSE 报告只引用临时别名、规范化报告恢复真实 ID，均通过。真实模型实验共两次调用，均已结束；常规测试与离线脚本不调用收费模型。
