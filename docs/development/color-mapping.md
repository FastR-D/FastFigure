# 多色素材的角色映射

第四十四批更新：色槽映射的用途说明 `role` 可缺省，程序明确记为“用途未注明”，不推断科学语义。配色、来源 / 目标索引、重复来源和数据图表保护保持；已采用风格 / 方案明确规定的映射仍须一致。一次真实字段遗漏及原响应离线编译见[本机召回实测](repository-recall.md)。

第三十六批，2026-10-30。在组件[默认主题色](component-color-bindings.md)之外，支持按来源色槽同时映射多个视觉角色，保持原生图元可编辑。

## 人工入口

容器属性选择“多色映射与预览”，查看当前范围使用的来源配色、原色槽、图元 / 连接引用数量与文字示例，选择目标配色及每个原色槽的新颜色，可填写“输入”“编码”“输出”等角色说明。角色由人或模型根据研究要求和标签确定，程序不从颜色推断科学含义。

弹窗提供修改前 / 预览结果，应用前不改画布；应用为一次可撤销编辑。画布已变化时须重新预览。可清空本层映射，子容器另可恢复父级映射。数据图表范围不开放此工具，系列和数值色阶继续使用自己的设置。

默认主题色改变未指定色槽的图元。多色映射则明确允许改变 `visual.colorIndex` 所引用的颜色，固定 RGB 的填充、描边和文字保持；文字、位置、尺寸、路径、端口和连接数组不被改写。透明度及线宽继续由原图控制。来源色槽按配色 ID 和索引识别，相同 RGB 来自不同配色时不会混为同一个角色。

## 规则与保存

映射保存在工程 `style.colorMap` 或子容器 `appearance.colorMap`，每层最多 12 项。每个来源只能有一条规则，来源和目标均须属于已知配色的实际色槽；旧式图件色系使用 `legacy:blue` 等来源标识及索引 0。例如：

```json
{
  "sourcePaletteId": "figureforge-publication-soft",
  "sourceIndex": 1,
  "targetPaletteId": "figureforge-publication-soft",
  "targetIndex": 2,
  "role": "隐藏层与内部连接"
}
```

全部规则针对原始色槽同时解析。交换 1→2、2→1 不会连锁覆盖成同一种颜色；未匹配的色槽保持。子容器有自己的映射表时，使用子表；没有子表才继承父表，空表表示本层不使用父表。引用同一色槽的神经元、结构图示和内部语义连接使用同一结果，固定 RGB 仍优先。数据图表及其后代不解析通用颜色映射，避免改变统计编码。

规则随工程、原生 SVG 元数据、组件捕获、缩放与保留原外观插入保存；SVG 使用相同解析后的颜色。继承目标外观插入属于主动更换样式，会采用目标的规则。

“保存当前风格”可从选定容器采集生效的映射，在风格编辑中展开“编辑风格颜色映射”可调整。风格允许携带当前图件未用到的规则，供其他图件复用；当前画板映射只允许新建实际存在的来源引用，未使用的既有规则可原样保留或移除。从绘图方案存为风格时保存全图规则；各组件的局部映射继续属于该方案。若要单独保存某个组件的规则，选择对应容器再保存当前风格。

## 助手入口

组件清单新增 `colorSlots`，包含真实来源色槽、原色、当前显示颜色、对象 / 连接引用数和文字示例。普通绘图实例可声明 `colorMap`，由程序校验后从源素材的外观展开并应用，原库组件不变；报告展示源色、目标色及角色。不得引用不存在的槽或对数据图表调用。

先规划时，`sections[].components[].colorMap` 可声明同样规则，目标须使用方案配色；不与该组件的 `colorIndex` 混用。采用后，程序把固定规则注入对应实例，模型返回的新规则不能替代已采用规则，也不能为未声明的实例添加映射。程序核对实际应用及来源，候选仍须由使用者审阅和应用。

## 真实调用与离线重放

用三张自制参考图、同一份原生 3–3–3–2 MLP 和 Quiet paper 风格做两次真实 Codex 调用。为验证多色映射，源素材输入神经元引用色槽 0，隐藏神经元与内部连接引用 1，输出神经元引用 2；要求输入青色、处理蓝色、输出橙色，没有直接填写目标索引。模型在方案中返回 0→0、1→2、2→1 及角色说明。开发助手读取方案后显式采用，不是独立的人类受试者评测。

| 阶段 | 运行 ID | 耗时与结果 |
| --- | --- | --- |
| 规划 | `04ed0726-cdf3-4001-9344-560bdfd672dc` | 86.555 秒，完成 |
| 生成 | `89ec4e8f-c694-4ccb-9be2-11ceafc73013` | 184.488 秒，被校验拒绝 |

生成输出使用局部 `appearance` 仅声明配色、色槽和继承皮肤，省略了 `accent`。旧契约把该字段视为必填，导致拒绝。本批将局部 `preset` / `accent` 的省略明确解释为 `inherit`，提示也列出枚举；显式非法值仍拒绝，全图样式、科学数据和几何约束保持。实际运行的模型身份未报告。原始失败、事件、输入 / 输出、图片、采用记录与执行前源码指纹保存在 `test-results/composition-color-roles-live-codex-v1/`，没有重写为成功。

修正后对同一份原始 JSON 做零追加模型调用的离线重放，经当前解析、方案注入、组件展开与风格核对生成候选，保存到 `offline-replay-v1/`。该目录的 `report.json` 明确标记 `offline-replay` 和原失败运行，保留原始响应指纹与最终源码快照。没有自动重试或应用用户画布。

实际查看离线渲染，输入层青色、两个隐藏层蓝色、输出层橙色；11 个神经元的 SVG 填充 / 描边和全部 26 条连接颜色经过检查，其中 24 条为内部连接。模型用一个透明的蓝色默认色容器表达两条外部箭头，原始局部样式缺省修正后同样生效。全部 14 个素材节点的种类、原文、字体、相对几何、语义色字段及两个命名接口保持，原素材不变；三个实际参考图字节与顺序指纹一致。文字检查为零项，路线均未被判定受阻，捕获素材保留映射与来源。

这证明本例的多角色规则能由模型提出并由当前程序编译；它不是修正后重新执行成功的真实运行，不证明真实论文质量、普遍科学正确性或 RSI 提升。固定 RGB、局部表优先、密集连线交叉和真实字形仍须审阅。

后续显式复验继续使用原脚本和全新输出目录，`--color-roles` 启用这份自制多色素材；规划后必须检查并输入匹配的生成命令。普通测试不调用真实模型：
