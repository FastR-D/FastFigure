# 原图与候选的双图视觉审阅

2026-10-29。本批为尚未应用的重建 / 分区修复候选加入区域视觉审阅：模型同时看到原图裁片和当前候选的实际渲染，只返回问题清单。用户可以定位并选择问题，准备下一轮修复，发送与应用继续由用户操作。没有自动评分接受、版本晋升或 RSI。

## 操作

在左侧助手的候选下展开“继续修复候选”，选择分区、修复重点与可选关注内容，点击“视觉审阅此分区”。审阅占用该会话的一次运行，使用助手设置的单轮时限，可停止。

完成后可切换原图、受审候选或并排图。点击问题标题在候选上定位，查看类型、严重程度、实际差异、建议与不确定项。文字问题同时显示两张图的模型转录。点击“准备修复此问题”，或勾选多个问题后“准备合并修复”，恢复受审版本、填入修复要求；点击发送后才生成一个新的候选，仍需审阅后应用。

报告只针对受审的固定版本。同一报告可选择至多 12 个可修复问题，合并为一个原子分区补丁，不会逐项回到旧起点覆盖此前修改。不确定、只读、范围外、文字转录不一致的问题不能加入。全选仅选择符合条件的问题；切换左侧 Tab 保留当前勾选。

修复候选记录所选问题和源报告，刷新后可恢复。点击“复审修复分区”，程序对这版候选重新生成实际渲染，与同一来源分区的原图送入另一个独立审阅会话；记录前一报告与修复版本的关系。复审仍可指出剩余差异或新问题，不把问题数减少或空报告解释为通过。

重新选择旧报告中的另一问题仍会从旧受审版本开分支，不会把旧报告直接套到新候选。要在较新版本上继续修复，先对该版复审，再从新报告选问题。画布发生变化时阻止准备旧结果或复审；报告、准备、发送、复审都不改写画布，最终人工应用整条候选链后可一步撤销。

这是一套显式的“审阅 → 合并修复 → 复审”操作。准备修复不发模型请求；发送和复审分别占用一次运行和单轮时限，没有自动重复至收敛、自动质量晋升或 RSI。

## 输入与渲染

浏览器优先从本地原文件缓存生成原图裁片，缺缓存时明确使用预览；沿用已验证的分区 / 原图 / 世界坐标映射。候选仅渲染相同重建组的内容，包含组内手工对象，不包含编辑标记或工程标题。两张图使用相同范围、宽高与白底；透明原图内容会对白底合成，不改变工程中的原参考图片。

候选渲染复用工作台 `createScene`，保持原生图元与绘制顺序。直接把含网页字体的 SVG 解码为图片会出现缺字，最初的本地实验已复现这个问题。本实现先加载浏览器字体，测量 SVG 文字的基线和变换，用 Canvas 生成字形图像，再在原顺序和变换位置合成形状。它只用于审阅输入，工程及 SVG / draw.io 导出的文字和路径仍为原生可编辑对象。

输入最长边 2000 像素，原图 data URL 最多 600,000 字符，候选最多 1,000,000 字符，总请求仍限 2 MB。文字精灵单边 8192、累计 32M 像素；变换后的字号在测量和剔除之前预检，避免 Chromium 在极端倍率下钳制字形、错把文字当成范围外空白。超限时在模型调用前提示扩大裁片范围或降低尺寸；多文字累计超限时可缩小内容范围。预检按整组文字保守执行。保留 renderer 标识和字体描述；这些描述不等于逐字形字体文件指纹。

候选整份 FigureIR 按稳定键序列化并计算 SHA-256，服务核对其与保存的父候选一致；同时验证原图来源、分区范围、图片头尺寸及两图宽高。指纹用于固定快照，不能单凭客户端声明证明像素确由该工程生成；本地渲染管线、实际图片留存与渲染回归共同提供对应证据。

## 模型会话与报告

审阅使用所选 Harness / 模型配置，另外创建并最终释放独立适配器，不继承绘图会话的消息，也不销毁原绘图会话。Codex 按顺序接收两个 localImage，Claude 接收两个 base64 image 内容块；顺序固定为原图、候选。图片、用户关注和几何目录作为资料，继续禁用工具、命令与外部服务。

当前自动目录仅提供按几何排序的临时别名、类型、位置和只读标记，不提供候选文本、原生对象 ID、分区标题、工程 / 来源名称。模型返回的别名先映射回本次固定目录里的对象，再执行原有文字核对、只读保护与后续修复。目录版本记为 `aliases-v1`；映射保存在本轮重型上下文文件中，随该轮清理。原始模型输出保留别名，规范化报告保留真实图元引用。

第十八、十九批的历史实验仍使用语义 ID / 分区标题，历史记录不改写。新的目录已去掉这些自动线索，但图像本身、对象类型 / 几何和用户显式关注仍有语义信息；复审时用户选择的问题标题也可能提示关注。它不是隐私匿名化或独立外部盲评，也不保证模型不存在先验偏差。成对实验和固定开发样例见 [目录去语义化](visual-audit-context.md)。

只接受 `{message,findings,uncertainties}`，至多 12 个问题。每项包含唯一 ID、类型、严重程度、差异、建议、归一化问题框与可选对象引用。拒绝越界位置、虚构对象、重复 ID 和混入 figure / patch 的结果。只读对象、分区核心之外和不确定的问题保留供人工查看，不直接准备模型修复。

文字问题必须分别提供 `sourceText`、`candidateText` 和转录确定性。程序用候选图元的实际文本核对 candidateText，经过 NFC 与空白规范化后不一致则保留问题但阻止直接准备修复。这个检查只核对已知的候选文字，不验证原图转录，也不能代替 OCR 或人工审阅；字形与 Unicode 表示差异可能需要人工确认。

空问题清单表示该区域未观察到明确问题，不生成“通过”结论。模型仍可能漏检或误判，尤其是小字、字体和语义。它没有自动改图权限。

## API、历史与实际输入

- `POST /api/harness/visual-audits`：sessionId、parentRunId、regionId、关注内容、可选模型 / 时限，以及两张实际裁片。父候选从服务读取，不重复传整份工程。
- `POST /api/harness/runs` 的 `auditRepair={auditRunId,findingIds}` 记录单项或合并修复来源，必须同时指定 `refineFromRunId` 和 repair task。服务读取已完成的本会话报告，核对受审父版本、分组、分区、所选 ID 及 repairable 状态；重复、虚构、混入额外问题数据、跨版本或跨区选择在模型调用前拒绝。
- 完整问题差异、建议、位置、对象引用和两图文字转录由服务附到实际提示中，不依赖用户可编辑草稿复制，也不会为了 12,000 字草稿上限截断长报告。草稿可补充要求；保护范围仍由既有分区补丁校验执行，问题引用不是更窄的图元修改白名单，缺失内容可能需要新增图元。
- 修复摘要保留 `auditRepair`（源报告、所选 ID / 标题、分组和分区）；新审阅的 `visualAudit.recheck` 关联源报告和这版修复。普通运行响应现也返回服务端 summary，客户端直接采用，刷新恢复同一记录。
- 审阅作为普通 Run 进入现有 SSE、取消、运行预算、20 份重型快照与 50 条轻量消息体系。摘要包含 visualAudit 元数据和 auditReport，不包含图片字节；报告不产生 proposal。
- `GET /api/harness/runs/:id/input-image` 与 `.../candidate-image` 分别返回本轮真正发送的原图 / 候选字节，no-store。界面验证解码和尺寸，切换 / 卸载时释放对象 URL。
- 图片被清理、损坏或读取失败时明确提示并可重试，不静默改用当前画布或重新渲染图片。轻量报告仍可在消息中查看。父候选已处理或清理后，修复入口会禁用或提示重新核对。
- 审阅期间保留受审候选；失败、取消或无问题都不修改它。后续修复重新读取父版本，沿用原始画布基准、只读保护、版本补丁和单步撤销规则。
- 所选问题修复运行时及失败后保留受审父候选；成功后保留新候选。报告图片被全局重型快照清理不删除仍保留的轻量报告与修复摘要；轻量记录也会按既有 50 条上限清理。不是跨服务重启的持久化。

## 真实模型记录与一次漏检

从先前保存的真实重建图生成受控损坏种子：将 Encoder 改成 Ecnoder，并移除蓝色曲线。种子由确定性 Scene 回放创建，不计为真实模型生成。源图为自制 800×400 简单图；实际审阅两图均为 328×268 的预览裁片。没有在用户关注中提示这两个预设缺陷，但目录中的语义 ID / 分区标题可能提供线索。

使用 Codex CLI 0.165.0，默认模型身份未被 CLI 报告，共两次显式审阅及两次所选问题修复：

1. 首轮审阅用时 46.782 秒，准确指出缺失曲线，却把候选错字误读为 Encoder，归因成略宽、略粗和基线差异。随后选择该文字问题的修复用时 40.149 秒。原报告和图片保留在 `test-results/visual-audit-live-codex-v1/`；该轮未保存完整提示字节，不宣称可逐字复现。
2. 增加逐字转录要求与候选文本核对后复测，用时 46.692 秒。报告同时指出缺失曲线与字母顺序错误，分别转录 Encoder / Ecnoder，与候选图元核对一致。选择错字修复后 15.687 秒返回正确 Encoder，其他分区逐字段不变，原始画布基准保留。曲线没有被选中修复，仍缺失；该候选不能称为完整重建。

两次审阅的原图字节相同（SHA-256 `5a7e1a582f33870469c1cfa38aeac3072b3e66c0dfde9d858acab9a6b9e2e751`），候选字节也相同（`1df502dd46657c69051987e4ad23cc85ed43837719018643b0b67076d7769197`）。第二轮完整提示、实际图片、原始输出、报告、所选修复与工程在 `visual-audit-live-codex-v2/`。这只是同图提示修改后的单次复测，模型有随机性，不能证明普遍准确率提升或作为留出评测。

显式运行真实调用，常规测试不会执行它：

```bash
node experiments/visual-audit-live.mjs \
  --seed test-results/repair-plan-live-codex-v1/final.fastfigure.json \
  --output test-results/visual-audit-live-codex-new
```

## 合并修复与复审的真实模型记录

2026-10-29，另一次显式实验沿用相同的自制受控损坏种子。初始图仍由确定性 Scene 回放，后续为 3 次真实 Codex 调用，没有自动重试或注入预设问题。CLI 0.165.0，默认模型身份未报告，实际两图为 328×268 预览裁片。

1. 审阅 `783c8f69-75d0-4741-81de-311e3ddd8034` 用时 51.513 秒，指出曲线缺失及 Encoder 拼写 / 字重问题。
2. 选择两个问题，服务验证来源并合并修复 `e7bc0b3a-8a09-4235-a42c-3926c87cf84a`，用时 89.579 秒；文字恢复 Encoder，蓝色曲线重新出现，其他分区逐字段相同，原始画布基准保留。
3. 对新候选渲染并复审 `8b3c6815-8b2a-44ea-82ff-3ad9ceac5c48`，用时 53.945 秒。报告仍指出“标签略大且偏低”，没有自动判定完成，也没有继续修改或应用。图形已补回不代表整体样式完全匹配。

记录在 `test-results/visual-audit-merge-live-codex-v1/`，包含三轮完整实际提示、原始输出、两组实际双图、所选问题、原生工程与指标。复审原图 SHA-256 仍为 `5a7e1a582f33870469c1cfa38aeac3072b3e66c0dfde9d858acab9a6b9e2e751`，新候选为 `2f941e4405aba31a2a94a7c55fcb877590376523cd260935e1af283cddb40cb7`，与旧候选不同。源码文件在实验结束后另存快照，附采集说明。这个结果仅验证一个自制简单图上的工作流与受控缺陷，仍有语义 ID 提示，不能外推为真实论文质量或盲评准确率。
