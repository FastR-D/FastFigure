# 分区核对计划

2026-10-29 创建，2026-11-06 更新。在候选版本链上执行用户选定的一次分区检查计划，结果仍为可审阅候选。它提供按区域顺序调度、状态恢复和回退基础，不进行自动视觉评分接受、训练或 RSI。

## 使用

在重建候选下展开“继续修复候选 → 批量核对分区”，按希望执行的顺序勾选至多 6 区。沿用上方修复重点和具体问题；点击“开始核对”。普通任务和分区核对均不设置自动运行时限，运行中可随时手动停止。

计划在本地服务中依次运行，左栏显示当前区域、各区结果。Tab 切换或页面刷新只恢复进度，不重发模型任务。关闭页面后本地服务中的计划继续执行所选区域；服务关闭会取消计划并清理进程。没有跨服务重启持久化。

空补丁会记录为“无内容改动”并继续下一个所选分区，不会把第一区无变化误当成其他区域都已正确。仅对象 version / 分组 revision 增长不算内容进展；图元顺序、内容、格式和来源变化仍会计入。所有分区各执行一次，不自动重试或重复检查同一区。没有改动时保留原候选，有改动时保留最近发生内容变化的候选；这不意味着它质量最佳。各轮仍可在消息中回看。

遇到模型错误、无效补丁或分区范围变化则停止后续区域，保留此前候选。用户可随时停止。在本页编辑画布会请求停止计划，最终应用继续按最初画布核对，整个版本链只记一次撤销步骤。其他窗口的编辑不由本页实时监视，最终应用的过期检查仍有效。

## 实现与边界

- `POST /api/harness/repair-plans` 接收 sessionId、parentRunId、content、可选 model、regions。候选从服务已保存的父运行获取，不复制整份工程到计划请求。
- 每区包含 regionId 和实际原图 / 预览裁片。逐区验证来源、范围、图片头尺寸；计划请求上限 4 MB、每片 600,000 字符、至多 6 片。普通单轮请求仍为 2 MB。
- 父候选须属于本会话、已完成且待审阅。只检查该候选对应的重建组；手工对象、其他分区、对象版本与原子补丁保护继续有效。
- 同一会话执行计划期间保留运行席位，拒绝额外模型运行、计划、候选处理和会话移除。全局仍最多两个活动会话占用模型执行席位。
- 固定计划中的裁片范围。若前轮修复令后续细节分区的实际范围变化，既有裁片不再匹配时停止，而不继续使用错位输入。
- `GET /api/harness/repair-plans/:id` 只返回状态与步骤元数据；`POST .../:id/cancel` 支持 cancelled / stale。会话 history 附带最近计划，session 列表标记活动计划，页面恢复优先连接已有活动计划。
- 客户端轮询进度并接回子运行 SSE。暂时断线只重读同一计划；不因观察超时或 503 创建新计划。计划完成后可以继续普通单轮工作，刷新不会强行打开较早计划而覆盖较新的会话详情。
- 最多保留 24 份轻量计划记录；完整运行仍按 20 份清理。计划结束后释放待执行裁片载荷，并优先保留该会话当前候选，防止一次无改动计划导致原候选被其他运行挤出。运行的实际已发送图片仍按现有快照策略保留。
- 50 条轻量消息的清理也保护当前候选和活动计划起点，按原始 ordinal 展示轮次；连续超过 50 次空补丁仍可查看并应用最初候选，不需要产生虚假内容改动来保住版本。

程序只把有内容差异的结果继续作为下一轮起点，不判断“变好”。因此这里没有自动质量晋升；仍需核对小字、连接、填充和语义。后续应扩展真实论文与人工标注、加入独立视觉评审及受控 A/B，再考虑重复修复或 RSI。

## 2026-10-29 原版真实 Codex 多轮记录

使用之前保存的自制 800×400 简单图重建结果，主动加入文字 `Ecnoder` 和椭圆鲜红填充两个缺陷。不是独立真实论文样本，也不是盲 OCR 评测。Codex CLI 0.165.0 使用默认模型，具体模型身份没有由 CLI 报告。

1. 单轮请求只修正错字，15.956 秒完成，其他对象保留，鲜红填充故意留到下一分区。
2. 启动 360 秒总时限、180 秒单轮上限的两个区域计划。椭圆分区在 21.806 秒返回填充修复，由 `#FF0000` 改为 `#F4DAC7`；源图目标浅杏色为 `#F2D8C7`，RGB 欧氏距离约 2.83。未在提示中提供目标十六进制值。
3. 编码器分区复核在 4.118 秒返回空补丁。该轮被记录但不取代最近有内容变化的候选；其余五个图元相对文字修正后的起点逐字段相同，最初画布基准保留。

三次调用使用预览裁片，尺寸依次为 328×268、188×118、328×268；此独立浏览器上下文没有原文件缓存。每次实际传输字节、原始输出、版本基准、计划记录、最终可编辑工程和 SVG 都保存在 `test-results/repair-plan-live-codex-v1/`。服务与运行脚本使用时的源码副本也保留。一个派生指标最初错误地将第二分区与椭圆修复前的版本比较，已基于保存输出改为比较该轮自己的 baseFigure；原模型输出和原指标文件均保留，没有重新调用模型。

离线原生结果与工程参考预览的栅格对照约 32 万像素，平均通道差 0.757、前景交并比 0.9981；文字基线等仍有差异。这些小样本数字不证明复杂论文图重建质量，也不作为自动接受门。

复现真实调用需显式执行，常规测试不调用收费模型：

```bash
node experiments/repair-plan-live.mjs \
  --seed test-results/reconstruction-live-codex-initial.json \

```
