# 助手增量绘图与流式候选

2026-11-16：普通绘图增加增量操作协议。模型声明变化，程序负责补全默认几何和样式；工程仍保存原生 FigureDocument 0.2，现有手工编辑、主题、组件、论文尺寸和 SVG 导出沿用原有结构。

## 三层数据

| 层 | 职责 | 主要内容 |
| --- | --- | --- |
| 模型绘图操作 | 科学对象、分组、关系与授权修改范围 | ID、标签、结构类型、角色、连接、布局请求；只发送变化字段 |
| 原生工程 | 确定、可编辑的实际几何 | 完整坐标、尺寸、端口、样式、路径、组件和可信来源 |
| 预览差量 | 将服务端已解析的几何同步到浏览器 | 变化对象、删除 ID、对象次序和基准／结果令牌；不重新发送图片字节 |

模型不再需要为普通改字回传整份工程，也不必逐项复制主题字号、配色与轮廓。新增节点可以省略尺寸和位置，程序根据文字、结构与可用空间放置；连接可省略端口，程序选择端口并沿用正交避障。`layout` 调用现有 flow / grid 布局；移动容器会同步平移后代。未知结构不会因标签叫 Encoder 就自动补出 Transformer，须明确声明 `structure`。

底层继续支持 token、张量、特征体、算子、队列、投影、基础形状、独立文字、矢量图标、编码器／解码器／注意力／MLP／卷积／检索／融合／存储内部结构、上下标与混合字体。高级原生路径、渐变、数据图表、组件复用和参数更新继续使用各自契约。普通补丁不能伪造图表观测、图片字节、命名接口对应、重建记录或素材来源。

## 一次性增量补丁

```json
{
  "message": "更新编码器说明，保持其余内容",
  "patch": {
    "base": "上下文中的 patchRevision",
    "operations": [
      {"op":"update-node","id":"encoder","changes":{"description":"使用者给出的新说明"}}
    ]
  }
}
```

操作包括 `add-node`、`update-node`、`add-container`、`update-container`、`connect`、`update-edge`、`remove`、`theme`、`layout` 和明确重画整图的 `reset`。讨论可只返回 `message`。省略字段保持；`visual`、文字格式和局部外观按字段合并。`remove` 自动清理关联语义边，非空容器需要 `cascade=true`；仍被路径绑定引用的目标会使整批失败。

`base` 是固定输入工程的冲突检测令牌，程序校验后才应用。它不承担身份验证或安全哈希用途。每次在私有副本上执行，最终统一经过原生工程校验；某一操作失败，整批拒绝。ID、引用、父子内容区、容量、路径绑定和字号约束均保留。补丁不与完整底图、组件实例或图表等专用操作混用。

## 随模型输出更新

```jsonl
{"type":"start","protocol":"fastfigure.patch.v1","base":"上下文中的 patchRevision"}
{"type":"patch","seq":1,"operations":[{"op":"update-node","id":"encoder","changes":{"label":"新的编码器标签"}}]}
{"type":"patch","seq":2,"operations":[{"op":"update-node","id":"encoder","changes":{"description":"使用者给出的说明"}}]}
{"type":"complete","seq":3,"message":"候选完成，请核对"}
```

每行一个完整 JSON，不使用代码围栏。网络 chunk 可以在任意位置切分；只有收到完整行才解析，只有整批通过结构校验才更新候选预览。每批最多 120 项、全轮最多 600 项，输出沿用 300,000 字符上限。`seq` 从 1 连续递增，重复、缺号、错误基准、非法操作和完成后的额外输出均拒绝。引用其他新对象的操作需在本批内自洽，不能依赖后续批次修复悬空引用。

服务端以 150ms 合并预览更新，生成带基准和结果令牌的 `proposal.preview` 差量事件。前端应用服务端已解析的实际几何，不重新测字或计算布局；已有图片像素从本地固定基准恢复。差量同时保存对象次序，支持删除、重画和重排。SSE 沿用现有序号、事件重放和重连恢复。

运行中的图仅显示在助手的“流式候选预览”，当前画布不变，不出现应用入口。缺少 `complete`、取消或运行失败时不留下可应用的半成品。结束时重新解析适配器返回的完整最终文本，生成统一的最终待审候选；点击应用后仍可一次撤销。模型仍返回旧的单 JSON 完整图件时沿用原链路。

本轮普通绘图（未附组件或采用方案）支持流式补丁预览。组件组合、已采用方案、数据图表与重建／审阅保留专用输出流程；它们不会把尚未校验的部分 JSON 直接套到画布。

## 提示负担与验证

普通绘图使用精简操作说明、主题 ID 目录和当前主题 guide；图标提供已引用、要求匹配及少量内置候选。存在程序管理的图表／参数组合／定位文字／路径，或明确要求高级路径时，继续提供原生或专用契约。不是删除底层能力来缩短提示。

核心检查覆盖原子性、旧基准拒绝、原生结构与主题展开、自动布局、SVG 往返、任意 chunk 切分、序号、截断、像素保留和差量重放。服务复用 Codex 子进程夹具验证运行期间预览和完整提交；双适配器原有文本流检查继续保留。PC UI 在现有助手流程检查实际流式 SVG、未完成不可应用、完成后的应用和撤销。夹具验证协议，不代表真实模型的科学或视觉质量。

实现入口为 `figurePatch.ts`（操作编译）、`figurePatchStream.ts`（行事务）、`figurePreview.ts`（已解析几何差量），以及现有 Harness 服务与前端。
