# 多子图共享图例

在“多子图编排 → 共享图例”选择 2–8 张已有折线、柱状或散点图，设置顶部 / 底部位置、字体和字号，在原图 / 共享图例预览之间比较后应用。当前要求同图表类型、完整相同的系列名称，以及一致的实际颜色、符号、线型和透明度。作者仍须核对同名系列代表同一方法或条件；程序不猜测名称等价，不改色凑一致，不截断或改写数据。

生成的共享组件由原生文字与符号组成，支持移动、等比缩放和字体编辑，可单步撤销。源数据、误差含义、缺失项、原图元及它们的 ID 都保留。这里只隐藏重复图例，不重绘坐标或回收图表内部原有留白。图例位置必须有空白，不能覆盖现有对象；初次面板编排可设置“底部图例留白”。多视图数据选型也可请求共享图例，程序先预留 64 个画布单位。

## 调整已有图例

“多子图编排 → 共享图例 → 调整已有图例”可选择一份生效关系，调整字体、8–36 画布单位的字号、自动换行 / 1–4 列、0–120 画布单位的条目间距及位置。列数不能超过条目数，条目顺序沿用原系列。新建也可设置列数与间距。

默认保留左上位置，以及各条目现有的字体、字号、间距和列数；字体选择保留、字号留空时，不会统一原本的混合设置。明确选择顶部 / 底部时，在原所属容器中居中放置。预览会显示实际前后尺寸、字体 / 字号、列数、间距和更新对象数；有变化后才可应用，可单步撤销。选中已停用的图例时保留该目标并显示原因，不转而调整另一份生效图例。

更新沿用原组件、符号和文字 ID，保留系列名、符号编码、共享关系、手工粗斜体 / 颜色和未请求修改的字体。内部额外对象保留内容、格式及相对位置；命名接口跟随新外框，外部引线保留绑定、偏移和说明，端点随原对象移动。源图表、原始数据及未选图件保持。图元和容器的绘制顺序不变。

空间不足、与其他对象或内部手工内容冲突、源系列失配时整次拒绝；不会移动源图或缩字腾空间。具有旋转 / 仿射 / 特殊基线的标签暂不自动重排，避免覆盖手工变换。布局使用原生外框和文字宽度估算，仍需查看实际字形、引线及遮挡。没有实际变化时保留原图，只返回报告；明确选择列数或间距可以重新排列手工移动过的条目。

## 源系列变化后的重新匹配

各源图通过正常数据编辑共同改名、换色、重排或增减系列后，可在原图例上“同步当前源系列名称与图示”。程序先核对所有源图仍为同一图型、完整相同的名称集合和相同实际编码；没有先修改源图来凑一致。只变了一张源图、图例与实际数据标记不符或源图型改变时，仍不能同步。

界面逐项列出当前源系列：名称完全相同会预选原条目，改名时必须选择对应旧条目，新增必须明确选择“新增条目”。每个旧条目最多用一次，不按位置猜测方法等价。映射的符号 / 标签沿用原 ID、混合字体、字号和手工文字格式；显示次序沿用旧条目，新系列追加。只改图示时保持现有位置；改名或增减条目时按原列数 / 间距重排，保留左上位置。仍可明确选择字体、字号或顶部 / 底部位置。

没有对应的旧条目会在预览中明确列为移除；任何连接或引线还引用它时整次拒绝。新条目增加两个原生对象，默认沿用旧第一条的字体 / 字号；仍受 240 图元容量、字号、空间与手工对象避让约束。删除条目后原列数超过剩余条目数时，需要明确选择较小列数或自动换行。新增的 ID 在预览中生成，应用采用该份预览；下一次应使用上下文中的实际条目 ID，而非继续把它声明为新增。

共享文字、图示、附加图标 / 注释、手绘外观或隐藏状态被独立修改时，不用源同步覆盖这些作者内容。原组内注释、命名接口与未移除条目的连接保持，引线端点跟随原对象。不会改写源图的原值、误差、范围、图示、文字或其他对象；也不会重写另加注释中的方法名称，需要作者核对文义。

这仍是明确预览 / 应用的操作。后续源图再变化不会自动改写其他图，也不保证方法改名具有科学等价性。

## 一致性与恢复

共享关系保存在独立组件的 `sharedLegend` 字段，记录源图表、系列名称、符号与文字 ID、标准化外观快照。比较时去除位置和缩放差异，核对实际图例与数据标记，包含颜色、符号、线型和透明度。共享文字的字体与位置可以单独改；改写其方法名、隐藏条目或改变符号会停用关系。

渲染与导出每次重新核对：源图表被删除、改系列、改色、重建图元或出现手工样式失配时，恢复各图原图例，隐藏旧的共享条目，并显示“共享图例已停用”。新增外部连接 / 路径绑定到原图例时也会恢复，避免隐藏连接锚点。共享条目从未从工程中删除，停用不会丢失作者改字或字体。

源图、共享图例及其祖先容器有整体 opacity 变化时，当前拒绝共享 / 同步并恢复原图例，避免忽略合成透明度。只改变容器背景的 visual.opacity 不影响后代图示，允许使用；共享标签被单独设为完全透明也会停用。

删除共享组件会恢复原图例；也可在该工具中“解除共享，保留可编辑副本”。后者保留现有共享图例为普通组件，同时显示原图例，作者可继续移动、删去或整理副本。每张图表只能关联一份共享图例；生效关系可直接调整外观和排布。规范源系列变化可按上述对应关系同步；共享条目被手工改写等失配仍需先整理或解除，不用样式更新覆盖科学内容。

热图使用独立的[共享数值色标工具](shared-colorbar.md)，箱线图沿用分组轴；混合图型、部分同名系列及自行猜测的系列匹配不合并。图表的误差棒、示例标记、注释和统计说明仍分别保留。当前没有自动重配色或静默的动态名称联动，样式、源同步与排布更新由人明确应用。

## 保存与助手

JSON 和原生 SVG 元数据保留完整原图例和关联，SVG 画面按当前有效关系显示。完整图件捕获 / 缩放 / 保留外观插入会重新映射关联 ID；只捕获单张图时显示它自己的图例，只捕获共享图例时成为独立可编辑快照。候选差异包含共享关联字段，助手事件和历史保留程序报告。

普通助手可单独返回 `sharedLegends=[{containerIds,placement,fontFamily,fontSize,columns,gap,reason}]` 新建一组。调整已有图例使用单数 `containerId`：

```json
{"message":"调整已有方法图例","figure":null,"sharedLegends":[{"containerId":"legend-ID","placement":"top","fontFamily":"MiSans","fontSize":16,"columns":2,"gap":18,"reason":"调整阅读排布，保留系列和来源"}]}
```

更新时 `placement` 默认为 `preserve`，字体、字号、列数和间距均可省略。每轮一组，不混入底图、范围同步、配方更新或新实例。`context.sharedLegends` 给出实际位置、每条字体 / 字号、布局与生效状态，程序产生 `operation=create/update`、`changed`、`before/after` 与 `updatedNodes` 报告；混合字体 / 字号不会被描述为统一值。无变化不生成候选。模型不能提供数值、图示、目标坐标、替换图元或检查结论。多视图推荐使用 `sharedLegend=true`，原始数据仍来自冻结表格。

显式源同步在同一更新请求中增加 syncEntries，必须覆盖当前全部源系列。previousLabelId 为旧共享标签 ID，null 明确新建；列表用于对应关系，显示次序由保留的旧条目决定。上下文另提供 syncReady / syncError、sourceEntries 与同名对应建议。示例仅说明字段，ID 应使用实际上下文：

```json
{"message":"按作者确认的对应关系同步","figure":null,"sharedLegends":[{"containerId":"legend-ID","syncEntries":[{"seriesName":"Reference","previousLabelId":"old-baseline-label"},{"seriesName":"Ours","previousLabelId":"old-ours-label"}],"reason":"作者明确声明 Baseline 改名为 Reference"}]}
```

sourceSync 实际报告区分 kept / renamed / added、encodingChanged 与 removed；只更新当前图例，不接受模型提供的图示编码。没有 syncEntries 的普通样式调整仍只允许生效关系。语义无法确认时应请作者说明对应关系，不依赖字符串相似度猜测。

关联记录的 `layout.columns` 与基准间距随工程、捕获和缩放保存；显示及请求间距为当前画布单位，按共享组件的 `metricScale` 换算，避免缩放后再次编辑跳回原尺寸。

验收复用原核心 / 服务文件与现有 1920px 编辑主流程：三类图型、原图元保持、失配回退、路径绑定、素材 ID 映射、原生 SVG 显示、多视图预留和报告、事件 / 历史、真实字体编辑与保存恢复。未新增维护脚本或 UI 流程。常规回归复用 `test-results/ui/editor.png` 与 `results.json`，不再单独截图。

第七十二批复用原文件增加一个缩放后更新场景，覆盖混合字体、手工格式、额外注释、命名接口、外部引线、重排、无变化及冲突拒绝。原报告传输场景同时检查更新 / 无变化事件与历史，编辑流程增加预览、应用和撤销 / 重做。当批为 555 项核心 / 服务检查、Lint / 类型 / 构建及四条 1920px 流程通过；后续清理与新增检查以开发清单当前记录为准。
